# 《达尔文农场》V6.2 迁徙与邻地运动：规则及 JSONL 排查指南

本文供测试者随 `.jsonl` 一起提交。**玩法规则按本文件解释；数值为当前代码中的候选值，长期测试后可调整。**本轮只涉及陆地种群的邻地运动诱导与自然迁徙，不改变捕食系统或天空、海洋、经济、突发事件的默认关闭状态。

## 先确认测试的确运行了 V6.2

- V6.2 使用独立的内部开关 `enableV62Mobility`，**默认关闭**。目前“种群数值模拟器”的连接游戏页面没有启用它的按钮；只在 Play 模式点击“开始测试”并导出 JSONL，测试的是场景原有规则，不能据此评价 V6.2。
- 当前 schema 4 的 JSONL `header` 记录了 `buildHash`、种子和 `landRules`，**没有单独记录 V6.2 开关或候选系数**。仅凭一份 JSONL 和本通用指南，无法证明开关已启用。正式收集 V6.2 玩家测试前，须先增加可审计的启用入口，并把开关、系数写入日志；在此之前只能使用明确设置 `v62Mobility=true` 的自动回放场景或 Model 专项测试。不要把默认模式的日志标成 V6.2 结果。
- 对照同一测试时，保留完整 `.jsonl`。文件必须从 `header` 开始、以 `end` 结束；`end.logSha256` 验证文件完整性，`end.replaySha256` 是规范化结果的复现确认码。缺少 `end` 的旧日志可以阅读，但不能作为已校验的完整测试证据。

## 确定的玩法规则

1. **邻地资格。** 只考虑双向相邻的陆地地块与陆生种群；高度差至多 1。目标最多有 5 个不同种群席位；同种到达可合并，不另占席位。
2. **预测实际迁出群体。** 来源数量 `N<95` 时不迁；否则标准预测人数 `n₀=min(100, floor((N+5)/10))`。目标地以 `n₀` 为上限，找出可持续食物足以支付成年维护的最大人数 `n`；若 `n<10`，这条路线无效。预测包括已有居民和本轮已计划到达者的竞争，不会在预测时扣减真实食物、能量或人数。
3. **统一生态收益。** 运动诱导与迁徙判断调用同一个邻地预测。草食种群读取可持续植物摄入，捕食种群使用现有合法食物关系和可持续猎物量。来源与目标均计算每只的净增长价值 `V=clamp01(0.5+(可支付出生数−预计死亡数)/群体数量)`；成年运动能耗已在维护需求中，不重复扣除。
4. **有效收益。** 目标净增长 `V目标−0.5` 至少为 `−0.01/天`，且收益差 `Δ=V目标−V来源` 必须大于 `0.002/天`。归一化收益 `D=1−exp(−(Δ−0.002)/0.04)`；否则 `D=0`，路线无效。`D` 在 0 到 1 之间，收益越大，增加逐渐变小。
5. **长期运动诱导。** 运动能力为 `m`（0–100）。平地连接系数 `C=1`；相差一级坡地 `C=0.6+0.4m/100`。上调 1 点运动能力的邻地收益为 `3×D×C×(1−m/100)/100`，还要加上来源地因运动能力变化产生的本地生存收益；下调方向按相应机会损失计算。只有净收益超过 `landRules.mutationGainThreshold`，才成为候选。候选权重为 `clamp(0.35×净收益/0.003×(0.22+0.28D), 0.05, 2)×selectionStrength`。自然种群数量与容量比 `N/K` 对其他自然变异的强抑制**不乘到这条 V6.2 邻地候选上**，但它仍与温湿度、体型、繁殖和玩家引导候选竞争当天唯一的变异席位。已有定向保护与影响方向限制仍生效。
6. **实际迁徙。** 迁徙检查仍按配置间隔执行（当前默认每 7 天）。平地要求 `m>30`，一级坡地要求 `m>60`，两级高度差不能迁。迁出人数为第 2 步预测的 `n`，范围 10–100。候选概率为 `clamp01(F×m/100×(n/n₀)×坡地系数×D×四席位修正)`：平地系数 1，一级坡地 0.5；`F=clamp01(目标可持续食物/max(1,目标可持续食物+成年需求)×气候连续系数)`，气候连续系数为 `max(0,1−0.2|温差|/100−0.2|湿差|/100)`。目标已有 4 个席位时，还乘现有 `landRules.fourEntryMigrationFactor`。按概率与确定性随机流决定是否执行；一次没发生不等于规则拒绝。
7. **落地与守恒。** 保留原有迁徙冷却（当前默认 7 天）、禁止直接返回刚离开的地块、同种合并、目标容量与先迁出后落地的流程。迁徙前后来源与目标的总只数必须相等；落地失败时个体返回来源地。

## 拿到日志后如何定位

先在 Unity 的“导出测试数据”页点击“校验导出日志”，或在工程目录运行：

```powershell
python Tools/ReplayLogAudit/verify.py "A.jsonl" "B.jsonl"
```

脚本先校验 `logSha256`，再按相同输入分组并指出首次不同的输出记录与字段。不同的 `buildHash`、初始快照、种子或玩家操作序列不能当作同一次复跑比较。`replaySha256` 相同表示规范化轨迹相同；它不证明生态结果符合预期。

| 看到的现象 | 先看 JSONL | 应检查的规则或参数 |
| --- | --- | --- |
| 运动能力长期不变 | `snapshot.tiles[].populations[]` 的 `movement`、`neighborAttraction`；同 `populationId` 的 `ecology.kind=mutation_choice` 中 `candidates`、`selected` | 先确认 V6.2 确实开启。开启后 `neighborAttraction` 是最佳路线的 `D`，**不是迁徙概率**。`D=0` 时检查邻接、高差、目标席位、可持续食物、`n≥10` 与收益门槛；`D>0` 但无 `v62_neighbor` 候选时检查本地运动成本、变异门槛和定向限制；候选存在却没选中时检查候选权重与唯一变异席位竞争。 |
| 达到运动门槛仍未迁徙 | `snapshot.day`、`count`、`movement`、`migrationReadyDay`、来源/目标 `height`、`water`、`recovery`、`plants`、居民数量；`transition.kind=Migration` | 先排除非迁徙检查日、冷却、`N<95`、平地 `m≤30`／坡地 `m≤60`、两级高度差、无目标席位。满足门槛仍可能因收益、目标食物不足或概率抽签而未迁；单份日志不记录每条被拒路线及抽签，需同版本重放或增加专项诊断才能精确归因。 |
| 迁徙后人数异常 | `transition` 的 `amount`、`sourceBefore/After`、`targetBefore/After`、`outcome`，前后 `snapshot` 的同 `populationId` 与坐标 | `amount` 必须在 10–100，且 `sourceBefore+targetBefore=sourceAfter+targetAfter`。违规则优先报代码缺陷，不通过调系数掩盖。`Merged` 表示同种合并。 |
| 两人结果不一致 | `header.buildHash/seed`、`initial` 快照、`action`、首次不同的 `snapshot.modelHash` 或 `transition/ecology` | 先比较版本与输入；输入一致才追首次分歧日、坐标、种群 ID、操作顺序。若生态或变异首次分歧，核对该日 `mutation_choice`、资源和随机流；不要直接改 V6.2 系数。 |
| 食物或捕食异常 | `foodSatisfaction`、`allocatedFood`、`energyNeed`、`plants`、`plantGrowth`、`plantConsumed`、`predationDeaths` | 先核对生态账本和合法捕食关系；V6.2 的预测只读，不应凭空增减食物、能量或种群。捕食系统重构不属于本规则。 |

### 每个问题请附上这 6 项

`JSONL 文件名`、`测试编号/测试者`、`期望与实际`、`首次异常 Day + (x,y) + populationId`、`对应 action/transition/ecology 原文`、`end.logSha256 与 end.replaySha256`。若使用专门的 V6.2 运行器，再附启用方式和参数；当前点击导出的日志不能自行证明这一点。

## 代码定位

公式与候选值：`Assets/Scripts/Simulation/V62MobilityRules.cs`；共用邻地预测：`SimulationController.V62Mobility.cs`；变异席位：`SimulationController.LandTraits.cs`；实际迁徙：`SimulationController.Migration.cs`；JSONL 导出和哈希：`Editor/PopulationSimulatorWindow.LiveExport.cs`。测试时应记录具体 `buildHash`，因为后续改动可能改变实现。
