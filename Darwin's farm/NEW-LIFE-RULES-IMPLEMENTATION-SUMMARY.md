# 新生命规则实现说明

## 与 v4.4 和新规的关系

策划案 v4.4 保留环境工具、地形、科技及地图流程；生命日结算采用用户提供的《生命活动规则定稿：可实现版本》作为较新的规则。其关键差别是：新规重新允许**有条件的同地块分支**、使用共享植物/猎物账本、按缺食率只结算一次死亡、按连续合格天数转化预设物种，并取消固定捕杀百分比。用户指定的出生系数默认 **0.1**、变异步长 **1**、变异周期 **1 天**优先于新规文本的建议值。

## 已实现

- Model 日结算：植物生长 `min(R,K-S)`；L2、L1、L0 顺序；共享猎物/植物账本；成体及幼体耗食、饥饿和寒冷死亡分别结算；10 日历史有限保存。
- 种群事件：原地分支、迁入同种合并、容量 5 条目限制、连续濒危注销、按性状/资源/持续天数转化预设物种。迁徙通过邻地吸引与运动门槛计算。
- 同种邻地不再提供运动变异的吸引加成，也不会成为自然迁徙候选；手动迁入仍可按原规则合并同种种群。
- 变异：每群每个周期只选择一个性状及一个方向；候选必须先超过可调的人均日净增长收益门槛，超额收益按可调尺度累计，因此接近门槛的变异更慢。候选评分与执行都作用于整支种群。邻地吸引只计入运动候选，最近一次实际变异效果保存在 Model、显示在种群详情和模拟器，并写入 `trait_mutation` 生态日志。默认每日、步长 1。
- 本轮数据回归：分化门槛仍为当前种群人数达到自身 `K_env` 的 90%，但 `K_env` 按该种群能使用的植物层更新量、利用效率和成年维持需求计算。分化的大体型创始支默认占 5%，此比例可调。未分化鸡利用底层植物的一部分；分化后小体型支使用底层，大体型支使用上层，两层共用同一库存账本。底层更新量默认占 70%，未分化利用效率 70%。植物正常恢复时日常摄食受更新量约束，恢复为 0 的冲击期允许库存耗尽。密度出生减速起点默认 85%。原导出字段 `k` 及其他 JSONL 接口不变。
- 2026-10-11 逻辑重审：当日出生减速由已存在成年群体的耗食负载决定；预计幼体需求按减速后的出生量计入植物分配。变异候选固定其他群体，只让候选体型和运动改变自身成年负载；温湿降低不再通过虚减幼体需求取得出生压力收益。捕食者候选的捕猎能力增减双向计入。分化和预设转化改用同一植物预算预测；迁徙吸引按成年需求及目的地适应度估算。猎物净新增在所有群体结算后统一读取，多个猎手按共享猎物扣除持续供给。
- 本轮生理口径：成年耗食包含过小体型的维持成本，过小体型另有自然死亡风险；生育生理负担改为跟随**实际出生数**，不再使用旧的固定死亡系数。运动提高觅食机会，同时增加耗食。体型对所属植物层的利用效率连续变化，不靠硬性体型阈值跳层。先前记录的鸡→鹿第 305 天正例来自旧公式，不能作为本轮结果；本轮依用户要求只验证两支鸡和直接同格鸡鹿的稳态。
- 配置：`LandRuleTuning` 暴露出生、耗食、竞争、捕获、分支、转化、迁徙等参数，复制并校验后供 Model 使用。独立种群模拟器提供中文参数控件；原有 JSONL 快照字段与原有迁徙/转化事件字段保持不变。
- 日志：迁入、分支、物种转化、局部灭绝、容量阻止和实际性状变异写入 `[Ecology]` Console 日志；分支复用现有 JSONL `transition` 字段格式，类型为 `LocalSplit`。
- 速度：`SimulationTime` 支持 1x、2x、4x，SpeedHUD 是可点击的 Button，按 `1x→2x→4x→1x` 循环；键盘 `2`、`4` 和模拟器按钮可直接选速。暂停后按钮从上次速度进到下一档，速度变化继续通过原 `OnSpeedChanged` 导出。

## MVC 与分支合并

生态状态及规则保存在 `BioData`、`SimulationController` 和 `LandLifeRules`；`GameInformationUI` 仅展示现有数据并把按钮点击交给 `SimulationTime`。已合并 `xizhen-2` 的地块/种群/趋势图 UI 与 `Vincent-Branch` 的瀑布资源。后者的四处 `.meta` 冲突保留项目现有 GUID，并把新材质引用指向保留的贴图 GUID。

## 验证结果与未确认目标

- 本轮正式源码回归：从单群鸡 160 只、T/H=68/68、`R=S=100000` 出发，第 102 天在 `N/K_env=0.904` 分化；第 5000～20000 天两支鸡分别稳定在 2046～2047、552～554，只数差异持续，五项性状固定，植物库存约 916034～916125。直接同格鸡 200／鹿 20 在 T/H=35/30、R=100000 下同期稳定为 2033～2034／547～549，植物库存约 916515～916606。高密度 50000 鸡、低库存 50000 的冲击测试未清零。出生系数 0.05 的同格鸡鹿也稳定；单鸡因未达到 90% K 暂不分化。环境从 50/50 改到 68/68 的单鸡回归最终适温适湿均到 68/68。以上由 `Tools/SelectionAudit` 链接正式源码验证，不是 Unity Play 模式结果。
- `Assembly-CSharp.csproj` 与 `Assembly-CSharp-Editor.csproj` 编译通过，`git diff --check` 通过；原有少量 Unity 类成员隐藏／未赋值警告仍在。旧 `Tools/NewRulesAudit` 的部分数值断言按旧食物与生理公式编写，不能用来判定本轮新稳态；本轮以新的长期回归程序为准。

- 原有迁入、转化与共享猎物测试属于此前实现的审计；本轮没有重新确认完整食物网和四物种链。SpeedHUD 手工步骤见[测试清单](NEW-LIFE-RULES-TEST-CHECKLIST.md)。
- 本机只有 Unity 6000.4.7f1，项目记录为 6000.2.9f1。批处理导入受 ShaderGraph 包版本编译错误影响，因此无法声称 Unity Play 模式已通过。生成的项目设置变化已清理。
- **15 分钟四物种链尚未被本轮验证。**此前首轮 JSONL 和旧公式复算数字仅用于定位原故障，不再是本轮新规则的预期；请按手工清单用 Unity 场景重新导出。
