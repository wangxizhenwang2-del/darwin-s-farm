## 1. 世界结构、关卡与系统开关

### 1.1 四边形世界

- 每个格为**四边形地块**，相邻由真实共享边与 `BlockInfo.neighbors`／地图实际连接共同决定；不因斜角接触就邻接，也不按六边形算6邻居。每格最多4个普通正交邻居，边界、缺地块或连接规则允许更少。
- 陆地海拔 `z∈{0,1,2}`；每次海拔操作只能 `z←z±1`，越界拒绝；相邻高度差0为平地，1为坡地，2为普通陆地断连。高差检查必须与生态位和邻地实际存在性共同生效。
- 环境：温度 `T∈[0,100]`、湿度 `H∈[0,100]`（均为指数，不是气温°或实际空气相对湿度）；日植物再生 `R∈[0,150000]`；现存植物 `S∈[0,10^6]`；碎屑 `D≥0`；真实本地种群列表。
- 27种陆地生境按 `z,T,H` 三档分类，映射既有八种视觉地形，分类以当前实际 T/H 判断；R/S 的直接变化不立刻重分类。默认矩阵见附录 A。海拔和气候造成生境变化时，更新后续**环境默认基线**，不能凭空改写已有实际库存，正在进行的已发布操作必须按自身恢复语义处置。
- 陆地植物是一份真实库存，不为每种生物或每个生态位复制库存。植物不建立动物 `Population`；生物逐**种群**模拟，无需单只动物级 AI。

### 1.2 四项独立功能开关 + 一键测试档案

| `EnableWaterEcology` | `false` | 不运行海洋／水域种群的生命周期与跨海陆转化；保留水域资产数据但不得利用水域完成核心测试 |
| `EnableEconomy` | `false` | 不做玩家货币／生物能支付限制、收入价格收割收益验收；**植物、猎物、成年维护、新生儿、进化生态物质仍真实付款** |

### 2.1 JSON 字段及核对

- `schemaVersion=1`，`species=15`，`evolutionLinks=20`，`foodLinks=25`。`species.id` 是权威物种标识；`name` 仅作显示，勿凭中文名拼接身份。图中可能有 Base64 形象文件数据，**不用于生态数值计算**。

## 3. 玩家环境操作、压力和撤销

### 3.1 五类环境工具／八个±方向 + 海拔±

| 类别 | 有效合法操作 | 环境实际影响 | 时序与撤销 |
|---|---|---|---|
| `S` 存量 | 当前库存的 `±25%` 或 `±50%` | 提交时 `S←clamp(S×(1±tier),0,Smax)`；`R` 不变 | **即时已执行交易**；无持续撤销，反向工具是新的资源交易 |
| `R` 日恢复 | `±25,000` 或 `±50,000` | 相对合法基线设目标 `R`，不瞬间把库存 S 加钱 | **25日进入、150日维持、100日恢复**，随时可撤销 |
| `T` 温度 | `±25` 或 `±50` | 向目标 T 缓慢插值 | 同上 |
| `H` 湿度 | `±25` 或 `±50` | 向目标 H 缓慢插值 | 同上 |
| `z` 海拔 | 每笔只能 `±1` | 立即改合法高程、重分类并重估连通 | 即时；若想改回须合法执行下一笔 ±1；不追溯已发生历史 |

- 有效环境变化才刷新相应引导：库存已满再点增加、越界、无效操作和纯 UI 预览不制造选择压力。环境与性状严格分离，玩家不能直接修改 `m,s,f,t,h` 或 K。
- 持续工具每块最多**两个活跃操作槽**（进入／维持）；新命令抢占时，先使旧命令进入恢复，保证阶段和优先级可审计；同类重投从**当前实际值**重新定义时间线，禁止跳值和双计。
- `25/150/100` 是**模拟日**。撤销进入／维持／恢复中的命令，应停止旧目标未来施压，从**撤销时实际值**用合法恢复期回归**本命令开始前保存的环境基线**，或对确实发生生境变更的情形按已确认的状态机确定当前基线；不能因为分类切换使撤销后的值反而朝错误目标发展。恢复中重复撤销是幂等，不重开100日倒计时。系统应记录 `baselineCapturedAtSubmit`、`currentActual`、`target`、`stage`、`cancelledAt`。
- 撤销不会倒带：已经扣除／增加的草、发生过的捕食／出生／死亡／进化／迁徙／性状变化均保留；只是未来环境和选择压力变化。历史 S 操作没有一条“持有150日的存量Buff”。
- **邻地吸引不属于工具按钮**。玩家建立邻地／修改气候／种群／高程会自然改变邻地收益，系统每日自动求压力。不能为此新增“邻地吸引+/−”科技、购买或撤销时间线。

### 3.2 十种历史压力方向的最终统一表达

这里是**八种环境正负变化 + 两种自动邻地机会变化**，不是十个独立科技按钮。

| 压力来源 | 主要作用 | 次要作用 | 类型 |
|---|---|---|---|
| 存量 + | 体型↑ | 繁殖↑ | 有效即时干预引导 |
| 存量 − | 体型↓ | 运动↑ | 同上 |
| 增量 + | 繁殖↑ | 运动↓ | 环境缓变所致干预／生态反馈 |
| 增量 − | 繁殖↓ | 体型↓ | 同上 |
| 温度 + | 适温朝 T ↑ | 体型↓ | 气候持续追随／干预次级 |
| 温度 − | 适温朝 T ↓ | 体型↑ | 同上 |
| 湿度 + | 适湿朝 H ↑ | 繁殖↑ | 同上 |
| **湿度 −** | **适湿朝 H ↓** | **体型↑** | **最新版**，不得重用旧繁殖↓ |
| 连通邻地更具价值 | 运动机会↑ | 无 | **自动持续环境诱导，非按钮** |
| 邻地价值消失／断连 | 运动机会收益衰减或归零；普通成本可能令运动↓ | 无 | 自动重新计算，非反向赋点 |

主要/次要只决定候选权重优先级，不是必达或直接赋值。相反方向引导必须按有效力度先净抵消，净值为0不产生虚假方向保护。T/H 的气候候选不是短期策略收益候选。

## 4. 每日结算顺序、对象与审计边界

在现有陆地 Unity 控制器里，通常是：**推进环境持续效果/当日阶段→地块植物再生与预算→合法捕食（取猎物活体）→植物共享分配→成年维护、完整出生付款与自然死亡→五 Bar 当日变异→全局濒危注销→正式进化→迁徙计划、拆离、落地／同种合并→更新地块和全局指标／日志**。这是一份与 Task 12 证据一致的工作顺序，**Agent 须核实工程当前 `SimulateDay`、`OnBeforeDaySimulated` 回调的真实先后**；如果顺序不同，先输出差异，不可以默默变更同日交易顺序来凑结果。

- 每个种群独立存放 `N`、五 Bar、模板身份、母子谱系、当前目标／保护状态、`energyReserve`、`bodyBiomass`、出生死亡小数余数、cooldown；不同地块同种不得误合并。
- 单日事件区分 `preLife / afterPredation / afterBirthDeath / afterMutation / afterEvolution / afterMigration`；原地指标更新和迁入目的地状态的首次消费效应遵循真实阶段，不允许“同日迁来立即重复吃一遍”。
- 代码生物网 `trophicLevel==0` 是**动物草食种**；食谱权限优先查询完整 JSON 的合法边，捕食者不能借更高等级或空列表回退捕食非法物种。

## 5. 五 Bar 自然选择、引导、目标与保护

### 5.1 五项性状与唯一机会

- 每群的 `适温 t / 适湿 h / 运动 m / 体型 s / 繁殖 f` 均是0–100范围内的种群级性状；实际模板五项来自 JSON 与相应 C# 模板。一次**每日结算最多一项改变 ±1**，没有同日两次变异；所有候选（气候、普通自然、玩家近期、邻地持续）竞争同一个席位。
- 气候候选只按 `t→T`、`h→H` 的真实温湿失配方向前进；温湿适应通常具有较高优先级；**不受 N/K 普通策略自然机会的阻断，不受三策略目标区间保护**，但仍不得同日双跳。
- 普通自然策略候选 `m/s/f` 分别按变化 ±1 时的**长期可持续净收益增量**评估，只允许正收益方向；本地稳态没有真实改善需求时不应仅因噪声微弱提高而持续无意义优化。需要反映资源不足、实际饱食、种群趋势、捕食和竞争。不同策略共用相同的可比评分标准与真实资源预测，不对一个物种特判。
- 近期玩家合法环境引导可提出方向性候选，即使即时净增长预测不为正也可形成短期诱导；但不取消真实付费或死亡，也不能变成无条件+1。引导未赢得统一席位可按旧机制积累短期潜力；有效引导结束未兑现的潜力按规则取消。
- **已确认方案 B：连通邻地长期运动机会**形成独立的**持续环境诱导候选**（详见第6章）。低于实际迁徙门槛时仍可有机会收益；不是新科技按钮，不直接迁徙，也不得绕过统一变异席位。该通道必须与气候、近期引导、自然补偿统一评分，不能靠无限倍率独占席位。若只靠旧 `N/K` 把机会候选直接判为不可见，视为不符合方案 B；在密度高时可以按统一概率降低**实际成功频率**，但不得把合法正机会直接硬置零。
- `N/K` 的普通自然机会现有一版代码近似 `p_natural=0.5−0.495 clamp((N/K)/0.95,0,1)`（`K<=0` 特别防零）。接近90%时显著衰减，非绝对归零；它不是生命值回复或 K 剪人口规则。新候选不得偷借气候候选资格绕开自己的资格判断。

### 5.2 三策略保护及追踪

- **近期引导保护**：有效净定向引导期间，防止同一策略 Bar 被相反普通自然候选立刻抹掉；反向有效操作先抵消后重新判定。仅有效的环境事务可刷新保护，**无效点击不能刷新**。
- **残留保护**：引导结束后有限时窗内缓冲反向自然回落；到期才自然释放。它是近期引导保护的一个后续阶段，不是永久保留引导收益。环境持续阶段与旧代码7日／5日的引导／残留窗口是**不同钟表**，不能拿7日记录代替150日环境真实变化。
- **目标达标保护**：自动追踪最近**合法、当前本地尚不存在**的相邻进化目标；可由玩家手动指定合法目标，手动优先；五项性状等权计算目标距离，切换有迟滞防抖。`m/s/f` 各自进入对应目标允许区间（旧基线通常 ±5）后可被保护不跨区间；`t/h` **任何时候不锁定**，继续随 T/H 适应。
- 若种群长期衰退、所有未保护策略正收益补偿不足，可以按保护建立顺序 **FIFO逐项解除**策略保护；解除只允许后续候选，不立即回滚 Bar。已经释放的保护不能因为性状还在目标范围里就无条件逐日重新加锁。新引导可重新建立保护；不能偷偷救活数量。
- 自动目标切换只更新与目标相关的区间与追踪状态，**不清空实际已变性状、环境操作、仍有效短期引导**；原本对新旧目标都有效的保护保持建立次序。正式进化要对所有合法目标**独立检查**，不依赖当前 UI 正追踪的目标，避免意外达标被压掉。
- 每群每日记录：`candidateSource`, `trait`, `direction`, `deltaUtility`, `weight`, `winner`, `protectionReason`, `N/K`, `targetId`, `targetDistance`, `protectedBars`, `releasedProtection`。用户与 Agent 不应把“数值靠近模板”误读成已经进化。

## 6. 已选邻地运动公式 B：递减的长期迁徙机会收益

> **定档政策：**本章公式的**结构和本轮校准试验值**已由用户选定，Agent 必须按此作为目标候选实现与验收；**不能把仅通过解析式性质检查写成已通过 Unity**。若真实生态收益尺度无法统一，报告阻塞／提供并列对照而不是擅自回到更老的饱和函数或直接修改运动 Bar。

### 6.1 核心计算（归一化评分，运动取0–100）

设当前地块 `b`、存在的合法相邻候选 `j`、同一测试种群在原地及候选地的**可持续生存机会指标** `V_b,V_j∈[0,1]`；两者应使用相同资源、捕食、温湿、竞争和人群密度预测口径，不能仅用温湿 `F` 或将现存猎物身体库存算成每日补充。分别考虑每一邻地对源群迁入后的真实竞争份额；不得把多邻地食物同时占为己有。

```text
c_j = 1.0  if 真实共享边、同生态位合法、|z_j-z_b|=0
    = 0.5  if 真实共享边、同生态位合法、|z_j-z_b|=1
    = 0    if 无边/不存在/跨被禁用生态位/高差>=2/其他硬不合法条件
A_b = max_j [ c_j × max(0, V_j−V_b) ]            # 空集合时为0
lambda = 2.5                                    # 本轮实验默认，不宣称终局平衡值

DeltaU_m_plus1 = lambda × A_b/100 × (1−m/100)
                − 0.4×(2m+1)/10000             # 参考成年能耗归一化边际成本
```

- **新增收益随运动递减**：`(1−m/100)` 防止一个较有优势的邻地就把运动持续推到100；`m=100` 不生成 +1 候选；`m=0..99` 才评估。
- **真实迁徙门槛与此机会函数独立**：低于平地 `m>30`、一级坡 `m>60`，仍可有连续机会收益，但此时不能实际迁徙。真实迁徙成功之后在新地重新算 `V` 和 `A`，不会带走旧地块的“收益 Buff”。
- **局部成年运动成本只扣一次**：上式 `0.4(2m+1)/10000` 来自 `A_adult=c_A(s+200/s)[1+0.4(m/100)^2]` 对纯运动成本除去 `c_A(s+200/s)` 后的增量。若实际 `ForecastLandGrowth` 的候选差值**已经包含运动能耗**，则整合评分中应改为 `NormalizedLocalNetGain(m+1)-NormalizedLocalNetGain(m)+lambda*A_b/100*(1-m/100)`，**不能再减上述成本一次**。两个路径必须在固定资源的隔离成本夹具下保持一致；不要把两个量纲不同的增量未经转换直接相加。
- **有效邻地更新条件**：建／拆地、合法海拔变化、温湿/R/S变化、源群或目标群的数量变化、出生死亡／捕食／迁徙／进化后都应重新估算。断连时 `A=0`，已经进化出的运动 Bar 不回档；普通生态成本可使之后 `m−1` 成为候选，不能无条件强迫 −1。
- **多邻地取最高一个**，不求和、不叠概率；这个“最好邻地”可以随日变化，候选地身份证明与优势要写日志。
- **0–1 价值标尺待实测对齐**：从统一 `ForecastLandGrowth`／食物竞争器取得本地与迁入后净生存预报，并以**同一归一化尺度**计算 `V_b` 与 `V_j`。本文件不捏造已冻结的绝对映射常量。Agent 必须报告选用的映射、量纲、裁剪区间、单调性、边界与依据，独立验收后方可把它设为默认。不得一边测试一边为每种动物单独调整 V。
- m−1 的自然变异按同一效用比较（需分别考虑已存在本地生存收益和机会减少），不能直接把 `−DeltaU_m_plus1` 当作它的正确值；应比较 `U(m-1)-U(m)`，防边界越界。候选收益转统一席位权重不得因单位较大而挤掉气候适应。

### 6.2 解析式测试的正确停止点表

**仅**假定从 `m=10` 出发，邻地相对优势和全部参数永远不变，所有正收益 +1 都必定发生，不含随机性／N/K／其他 Bar／生态变化。下表是**理论可增长到的运动点数，不是完成天数、概率或真实 Unity 终值**。

| `V_neighbor−V_here` | 平地 `c=1` | 一级坡 `c=.5` | 不连通 `c=0` |
|---:|---:|---:|---:|
| 0.0 | 10 | 10 | 10 |
| 0.1 | 24 | 14 | 10 |
| 0.3 | 49 | 32 | 10 |
| 0.5 | 61 | 44 | 10 |

**必须复验的性质**：无边/优势≤0不产生**邻地来源的运动↑收益**；优势变大不降低运动机会；运动越高机会递减、成本递增；不会超过100；低运动可以先积累再跨实际迁徙门槛；在任一天失去邻地机会，不会凭空创建逆向瞬变；重复运行逐日哈希一致。以上局部性质通过，不等于本测试能把菇狸35和鹿72都做出来；若72不可达，先看实际 V 和操作路径，不要修改物种模板。

### 6.3 真实接入接口建议（尊重已有源码）

- 读邻地：沿用现有 `ReadLandSelectionSignals`／`BestNeighborAttraction` 或等价接口，**不得新增科技按钮**。
- 运行顺序：`getLegalNeighbors`→`forecastV(origin)`→`forecastV(each destination with residents)`→`bestOpportunity`→`m±1 candidate`→统一候选合并／N/K安全门／保护校验→唯一变异槽→真实变异及后续迁徙。
- 追踪字段建议：`bestNeighborId,zDelta,V_origin,V_dest,reachCoefficient,opportunityA,m,deltaUtilityPlus,deltaUtilityMinus,localCostAlreadyIncluded,candidateAccepted,rejectionReason`；没有日志证据就不能声称已经接线成功。

## 7. 正式进化：唯独10%物种分化；普通5%分化彻底取消

### 7.1 取消旧机制（最高优先级代码变更）

- 禁用并清理**普通 `local_split` 路径**：N>200、10日高饱食、N≥.9K、`splitFounderFraction=.05`、定向向后继模板调 m/s/f、50日锁、旧的仅为普通子支建立的50/100/200日合并冷却和独立同种克隆。不能保留一个默认开关让其在综合测试时偶然触发，也不得把普通分支事件重命名冒充 `PresetEvolution`。
- 如果某条**真实迁徙**进入已有同种居民，仍需要合法**同种合并**；取消普通分化不等于取消迁徙合并。普通分化曾产生的历史存档、字段、事件 ID 要做迁移或兼容处置，不得因删除功能而静默删掉历史种群人数和身体物质。
- 在历史 `local_split` 仅用作测试对照的地方，可保留外置只读归档，但当前生产逻辑与新测试禁止执行。若生物网其他阶段实际依赖它作必需输入，明确标记 `BLOCKED_BY_REMOVAL`，不能暗中自动开启。

### 7.2 唯一合法的正式物种转化

- 进化关系必须是同包图中合法的相邻**双向候选**；源群与目标种的五 Bar **逐项**在目标容差内（代码基线通常±5，必须输出运行参数），满足数量、当前／再生食物、连续达标日、冷却、目标生态位开启与本地目标物种缺席的所有硬条件。正式进化不依赖 UI 正在追踪哪一种；每个合法目标独立维护连续达标计数。
- 正式进化从母群按 `round(0.1N_source)` 计划人数，至多保留母群至少1只；**没有迁徙上限100只**。真实食物／猎物合法付款不足则**按能付起的数量减少**，不允许凭空生成身体物质，付款实际为零且无需补差时不能凭空把母群身体质量改轻却不记差额。若正式数量或最低合法门槛不满足，则不执行。
- 母群保留原物种和即时五 Bar，人数扣分化数量；新子群取得目标种真实模板五 Bar、营养级、生态位和**白名单食谱**；双方各自独立目标/保护；子群不继承母群有效保护和定向收益。物理环境属于地块，仍施加于父子群。
- 若**本地已存在目标种**，禁止同地再次进化到这个物种；其他地块已有则不挡。迁入使原追踪目标失效时即时寻找新的合法目标并更新保护，不能因为全局曾出现过目标就永久禁用。

**身体物质补差合同（现有 Unity 工程需逐项核对）：**

```text
raw = round_half_up(0.10 × N_source)              # 取整方式应与日志核对
requested = min(raw, N_source−1)
bodyPerSource = bodyMass_source/N_source
bodyPerTarget = 40×max(1,targetSize)              # 若调参文件不同，以运行配置导出
positiveGap = max(0, bodyPerTarget−bodyPerSource)
affordable = positiveGap>0 ? floor(legallySpendablePlant/positiveGap) : requested
n_new = min(requested, affordable)
plantPaid = n_new×positiveGap
bodyExcessToDetritus = n_new×max(0,bodyPerSource−bodyPerTarget)
```

本例植物付款适用于当前陆地合法来源及测试代码；若目标是食肉物种，**进化后**必须有合法猎物支持的生存门槛，不允许只凭一笔植物付款就假设其能长期猎食。每个事件账应记录交易阶段前后实际植物、活体身体和碎屑，`n_new>0` 才算真实 `PresetEvolution`。

## 8. 植物生产、食物分配与维护账本

### 8.1 当日植物增量及唯一预算（V5.2 当前陆地算法）

定义地块期初 `S_t`、今日合法真实增量 `R_t`、库存上限 `Smax`，以及当天新长出的 `G_t`：

```text
G_t = min(max(0,R_t), max(0,Smax−S_t))
S_afterGrowth = min(Smax,S_t+G_t)
g = clamp(G_t,0,S_afterGrowth)
standing = max(0,S_afterGrowth−g)
softFloor = R_t>0 ? min(0.10*Smax,0.5*S_afterGrowth) : 0
stockDraw = R_t>0 ? min(max(0,standing−softFloor),0.10*standing) : standing
P_today = max(0,min(S_afterGrowth−softFloor, g+stockDraw))
C_plant = sum_i foodAllocatedToHerbivore_i,    0≤C_plant≤P_today
S_afterPlantEating = S_afterGrowth−C_plant
```

- `P_today` 只是**唯一物理库存 S 的当日可领取预算**，不是新储库。其定义决定短期多库存与长期恢复能力是不同的；**瞬时 S 提高不能冒充永久 R 增加**。
- 玩家 S− 从实物 S 减，S+ 是有审计记录的外源生态输入；实际进化支付也从真实 S 扣，不重复从 `P_today` 扣。同一天操作的先后必须与事件日志一致。
- 大小食草生态位通过**分配偏好／采食效率**在同一预算里竞争；已吃饱者退出迭代并让未消耗预算继续给有需求群。**所有群成年维护优先于任何出生付款**。

### 8.2 气候适应度、成年维护、新生儿成本

```text
F_i = clamp(1−(|T_b−t_i|+|H_b−h_i|)/90, 0, 1)
A_i = adultMaintenanceScale×(max(0,s_i)+200/max(1,s_i))
      ×(1+0.4×(clamp(m_i,0,100)/100)^2)
Y_i = 0.4*s_i+0.02*s_i^2
BodyPerNewborn_i = 40*max(1,s_i)
NewbornTotalCost_i = Y_i+BodyPerNewborn_i
```

这些是已读取历史陆地代码的**默认公式**，运行时资产覆盖值必须单列。`adultMaintenanceScale=1.0` 是旧代码默认；`0.40` 是 Task 8 后续 Unity 测试使用过的实验配置；不因此自动宣告它已经成为每一场景的默认。`reproductionStressPerBirth=0.8`、猎物半饱和系数 `0.58` 同理记录为历史研究候选。

### 8.3 食草共享竞争分配（不复制草）

- 单群成年请求 `D_i=N_i*A_i`。成年全部优先迭代分配，权重来自**真实** `F_i`、体型植被可及性、运动觅食效率和专精／非专精偏好。旧函数常量：`forageSizeScale=20`, `forageMovementScale=10`, `forageAccessLossAtZero=0.08`, `movementForagingGain=0.002`, `smallPlantSizeScale=20`, `largePlantSizeScale=25`, `unspecializedPlantEfficiency=.7`；Agent 核对生产代码和运行参数。
- 参考体型通道效率：`small=1/(1+(s/20)^4)`；`large=(s/25)^4/(1+(s/25)^4)`；运动辅助从实际 `m` 而来。若更改效率公式必须有对照模型与单生态位、混合生态位回归。
- 每个群不超过自己的需求，不因种群遍历顺序获得额外资源；全群成年完成后再分配完整出生所需的维护和身体物质。未支付的整数新生儿不得生成。
- **70/30历史候选**：`smallPreferred=.70 P_today`、`largePreferred=.30 P_today` 仅为两种偏好**虚拟预算优先权**，对方未用真实余量可以流转；不能分成两个实体 S，也不能一份余量被消费两次。保留可回滚开关，启用状态需明确、验收后再锁默认。

## 9. 出生、自然死亡、储备和身体物质

### 9.1 整数出生与先成年后幼体

```text
adultDemand_i=N_i*A_i
sat_i=adultDemand_i>0 ? clamp(availableFood_i/adultDemand_i,0,1) : 1
birthOpp_i=N_i * birthRate * (f_i/100) * F_i * sat_i
possibleBirth_i=floor(birthRemainder_i+birthOpp_i)
birthBudget_i=max(0,availableFood_i−adultDemand_i)
born_i=min(possibleBirth_i,floor(birthBudget_i/NewbornTotalCost_i))
```

历史代码 `birthRate=.1`，现实配置按当次导出。`birthRemainder` **只保留小数概率余量**；未支付整数机会当天失效，不能留作欠账下日免费出生。先完整付款成年维护，再付 `born_i×NewbornTotalCost_i`；其中身体物质是**从食物转到新生身体**，并非另一份外源能量。

### 9.2 生存、压力与真实余数

```text
D_starve=.6*N*(1−sat)
D_cold=.005*N*max(0,(50−T_b)/50)
D_climate=.01*N*(1−F)
D_base=N*(.008*20/(20+max(1,s)) + .5/(1+max(1,s))^2)
D_totalExpected=D_starve+D_cold+D_climate+D_base+D_birthStress
```

- 生育压力**只能来自真实付款出生**；`born=0 ⇒ D_birthStress=0`。历史候选：`D_birthStress=born×stressCoeff×clamp(f/100)×Y/max(1,s)`，Task8 `stressCoeff=.8`、较旧代码 `1.2`。哪个已在目标工程默认运行，**要靠实际配置核对**。
- 其他饥饿、气候、寒冷、自然死亡独立结算，不能因为没有出生就不死。死亡人数小数余数积累取整且最多扣现存活体；灭绝后的余数不得杀死下一次合法迁入的种群。真实死亡身体物质转碎屑或明确汇，不能凭空丢失。
- 能量储备只来自**真实已领取未使用**植物／猎物，受成年维护需求的合法 `reserveDays` 上限（旧默认10日）限制；超出余额要列溢出／代谢汇。食草收入、猎食收入、出生付款和储备再利用均不得重复记账。

### 9.3 群体内部物质不变量

```text
legalReserveBefore + actualFoodReceived
 = adultMaintenancePaid + newbornMaintenancePaid
   + newbornBodyMassTransferred + legalReserveAfter
   + namedDissipationOrOverflow
```

活体质量变化须分出：新生增质量、自然死亡转碎屑、捕食转猎手或碎屑、正式进化转身体及植物补差、合法迁徙转地点。**任何一个内部转账都不创造世界生物量。**

## 10. 捕食关系、旧方案与 V6.1 统一候选流程

### 10.1 不可更改的约束

1. 有向 `foodLinks` 是唯一捕食白名单。高营养级不能仅凭等级吞吃未被连接的物种；菇狸不能吃鹿，孔雀不能吃彩鸡。
2. 捕食者有真实成年能耗，猎物数量、猎物身体质量、捕获能量、猎手余额、碎屑逐项真实收支；猎物少会减少实际捕获机会，猎手不能无限把猎物存量当成每日再生。
3. 同一种猎物的每日更新配额与真实活体只数是**多捕食者共享上限**；多个捕食者不许各自使用全部 `Q_p`。不允许“隐藏最低存活只数”或硬保活。捕食压力仍可能造成真实灭绝，但任何灭绝都要解释来源。
4. 捕食者的动态食物 K 根据合法猎物的**可持续更新**与其他捕食者竞争估算，不能靠真实猎物活体库存推定无限持续供给；L1猎物被L2捕食时也要采用同一账本逻辑。

### 10.2 保留为历史对照的两套机制

| 历史方案 | 表达式 | 状态 |
|---|---|---|
| A：猎物密度折减 | `F_density,p=N_p²/(N_p²+H_p²)`；食草猎物试验 `H_p=0.58×R_ref,p/A_p` | Task6–9 的候选／实机实验；`H` 的参照需固定并防止 R_today=0 时保护失效，不可直接套 L1 食肉猎物 |
| Q：可更新猎物配额 | `g_p(N)=预计无捕食可付出生−非捕食死亡`；有平衡 `N_eq` 时 `buffer=(N−0.35N_eq)/45`；`Q_p=floor(clamp(max(0,g_p+buffer),0,N))` | Task10 实验参数；L0曾有局部 Unity 证据，不表示完整食物网已通过 |

**保留历史开关和基线报告用于 A/B 比较；不能删掉原实验记录或声称原配额已经全链路验证。**

### 10.3 V6.1 统一捕食候选（执行顺序选定，参数继续待验）

按合法猎物 `p` 和全部猎手 `h`：

```text
1. 读取 foodLinks 中合法 (p→h)，计算现有原始猎食意向 I_hp>=0
2. 按猎物真实存活 N_p 和可解释的半饱和 H_p 得到 F_p∈[0,1]
3. 在不重复计算本轮捕食条件下，预测猎物真实可付款出生与非捕食死亡，求 g_p(N)
4. 用 g_p(N)、条件平衡 N_eq 和安全缓冲计算 Q_p∈[0,N_p]
5. 该猎物总捕杀 C_p = min(N_p, Q_p, sum_h(I_hp × F_p))
6. 将 C_p 的整数实际捕食份额按已定义竞争算法分给所有合法猎手；真实猎物只扣一次
7. 猎物身体 → 猎手实际所得 + 碎屑；捕食者真实收益与下一日 K 使用同一可持续供给口径
```

其中 `C_p` 计算前是可实现的连续预算，实际扣只数要遵守分数余数、随机数/确定性结算，不得超扣或将被禁止的整只机会记成下日免费配额。**旧捕食几率**可作为 `I_hp` 的起点：

```text
chase=clamp(1+(m_h−m_p)/40,.1,1.5)
sizeFactor=clamp(((s_h+10)/(s_p+10))^2,.1,1.5)
captureChance=clamp(.5*chase*sizeFactor,0,1)
preyBodyRemoved=actualKills*(actualPreyBodyMass/max(1,N_p))
preyBodyRemoved = hunterEnergyFromKills + detritusFromKills
```

**当前尚未被证明可直接作为全部L0/L1猎物默认的部分**：`V`和 `Q` 在高营养级与多地块的预测方法、`H_p` 对食肉猎物的基准定义、共享限额如何支持可持续捕食者、`0.35/45/0.58` 对全部种群是否过于保护或压制。Agent 应保留实验开关，先做旧 A、旧 Q、A+Q联合候选的隔离比较；只有通过完整白名单、资源守恒、逐日捕食和长期稳态回归后才能设置默认 `true`，不能默默把 `Q_p=∞` 或调出生绕过。

## 11. 动态 K、N/K 和独立容量概念

### 11.1 三种不同容量，禁止混称

| 名称 | 定义 | 不允许的解释 |
|---|---|---|
| `K_today` / 代码 `carryingCapacity` | 当天实际分配的食物相当于多少成年日维护，约 `allocatedFood_i/A_i` | 不等于长远净增长或稳态容量 |
| `K_food`（可持续食物） | 固定其他竞争群，使用可持续 R（不把短期 S 当永久生产），复用同一个成年食物分配器，以**反事实目标人口 n**二分可足额供应的最大 n | 不对人数设上限；不复制新食物，不硬推 N=K |
| `K_eff`（生态长期平衡） | 将真实可付出生、自然死亡、捕食、竞争及必要迁徙反馈代入，在完整动态系统里检验长期净增长趋零的可能平衡／区间；可能不存在唯一根 | **尚无完整已验公式**，不得把 K_food 宣称稳态 K_eff |

### 11.2 植食者 K 的 Task 12 已获实机证据的修复

旧 `environmentalK` 使用类似 `max(0,R×单赛道份额×单赛道效率−Σ其他植食者总成年需求)/A_i`，在彩鸡实际已获得足够食物时仍会算 `K_old=0`，导致 `N/K` 选择机会被误压低。**保留 Task 12 证据支持的修正方向**：

```text
R_eff=min(max(0,R),Smax*(1−min(.5,reserveFraction)))
K_food_i = max{ n>=0 integer |
    SharedAdultAllocator(targetN=n, otherN=fixed, plantSupply=R_eff)
      .allocatedToTarget >= n*A_i }
```

固定竞争者而改变目标种 N 是**反事实**，不是把人口真的写成 n。邻居迁入、种群分化进化、捕食、草量恢复变化时须在正确阶段重新评估；只读 K 计算不得改变随机数状态、实际库存或出生死亡。Task 12 在隔离 Unity 对照中，旧方案彩鸡第750日28只、第1150日灭绝，修正试验约为591只/623只；**这证明特定旧 K 错误得到修正，不证明捕食者 K 或五物种完成**。

### 11.3 捕食者 K 与人口变化

- 反事实捕食者食物供给 `Q_p` 使用合法猎物的**可持续净更新**，考虑多猎手共享；相同一份猎物净补给不能被不同猎手各计一次。若只有短期巨量猎物存量、无持续更新，K_food 应反映不可持续风险。
- `K=0`、`R=0`、`N=0`、竞争者0、最小动物人数都要防 NaN/负数；**K 绝不硬截断 N**。真实 N 只能由合法出生、死亡、捕食、进化物种转移、合法迁徙（全局对同种守恒）、有证据的濒危注销等规则更新。
- 自然变异机会接近 K 时应降低，不能把 K 超载当作“强制大跳变”或“快速免费进化”。

## 12. 真实迁徙、同种合并与守恒

- 平地实际迁徙须 `m>30`，一级坡须 `m>60`，高差2阻断。标准迁徙检查节奏旧代码约每7日一次；还须合法源／目标、有正吸引、种群冷却、目的地容量和随机决策。运动长期收益**不代替这些实际门槛**。
- **迁徙计划人数正确规则**：`raw=round_half_up(0.10*N_source)`；若 `raw<10` **取消**；否则 `migrants=min(raw,100,N_source)`，再考虑目标可接受容量；若实际允许数量不足10，仍取消，而不是为凑10透支源或目标。既不允许负人数也不允许超过100。
- 当前旧代码的 `clamp(round(.1N),10,100)` 可能在 N=50 时强行迁10只，**必须修正**。检查 N=11、50、90、99、100、1000，并与无体力、不可连通、目标拥挤情况组合。
- 同一种动物迁入已有同种居民时按合法加权合并，并对人数、身体物质、余数、储备、谱系和冷却做审计；这是**迁徙合并**，不是已取消的普通5%分化。迁徙事件应批量规划、先拆离后统一落地，防止新来个体同日多次链式迁徙或反向迁徙的事件级记账错误。
- 单条事件 `N_source_after=N_source_before−migrants`，`N_target_after=N_target_before+migrants`（同种合并也满足）；只看该事件时 `Δ全世界该物种数量=0`。同日出生／死亡／进化必须另列，防止拿全日净变化冒充迁徙不守恒。
- Task 12 真实机制夹具曾有23次迁徙且21次同种合并，运动80由测试初值给定；这**不是**自然低运动从鸡演化后迁徙的综合证据。综合测试只需少量有生态原因的真实迁徙，不规定20次。

## 13. 全世界生物量和全物种人数总账

### 13.1 物质量的逐日身份

```text
W_t = Σ_b (livingPlantStock_b + detritus_b)
      + Σ_pop (bodyBiomass_i + legalEnergyReserve_i)
      + 其他当次开关确实启用的实体生态储库

W_(t+1) − W_t
    = actualPlantGrowth + legitimatePlayerStockInputs + otherNamedExternalInputs
      − adultMetabolicDissipation − youngMaintenanceDissipation
      − namedOverflow/Sinks − legitimatePlayerStockRemoval
      + floatingResidual
```

- 捕食、自然死亡回收、迁徙、成年储备消费、出生身体生成、正式进化补差等为**内部转账**；不可凭空新造能量，也不能把同一植物消费同时记成年与出生。
- 玩家经济关停只意味着不查价格，**不会令玩家 S 操作失去其真实加草/减草外源生态入出账，也不会令出生和进化免费**。
- 允许显式代谢／系统汇，但必须按实际来源和去向记录；每日日账提供最大绝对和相对残差，容差以引擎浮点数与事件规模可复算，不得用大宽限掩盖漏计。

### 13.2 全物种人口账

```text
N_species(t+1) = N_species(t)
  + paidBirths − naturalDeaths − predationDeaths
  + formalEvolutionIn − formalEvolutionOut
  − explicitlyLicensedEndangeredRemoval
```

普通5%分化已禁用，因此**没有新的 local_splitOut/In 项**；合法跨地块迁徙对同种全局 N 相消；正式进化会使不同物种之间转移人口，但全动物只数未因此凭空增加。任何死亡都要以自然／捕食／濒危注销明确分类，不能混算。

### 13.3 每日最少日志字段

- `header`: `rulesVersion`, `sourceGraphHash`, 四项 flags, Unity build/source hash, seed, initial species/templates, model tuning, player operation mode。
- `tile/day`: `day,block,neighbors,z,T,H,R,S_start,G,plantBudget,plantConsumed,S_end,detritus,stage,activeActions,stockTransactions`。
- `population/day`: `speciesId,popId,N_start,allFiveBars,F,sat,adultNeed,adultPaid,foodFromPlants,foodFromEachLegalPrey,reserveStart,reserveEnd,paidBirths,possibleBirths,naturalDeaths,predationDeaths,N_afterLife,formalIn,formalOut,migrationIn,migrationOut,N_end,bodyMassStart,bodyMassEnd,K_today,K_food,K_eff_ifAvailable,N_over_K,target/protection`。
- `mobility/day`: `origin,bestNeighbor,deltaElevation,V_origin,V_neighbor,opportunityA,lambda,c,m,DeltaU_plus,DeltaU_minus,chosenCandidate,reasonIfRejected`。
- `event`: 进化／迁徙／撤销／操作有效性／食物支付／捕食共享配额，记录真实前后状态与资源付款。
- `dailyAudit`: 全动物人数收支、植物+身体+储备+碎屑实物账残差、可复现逐日哈希。
