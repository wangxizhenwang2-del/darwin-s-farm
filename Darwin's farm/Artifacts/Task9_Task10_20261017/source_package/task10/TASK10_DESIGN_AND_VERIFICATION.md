# Task 10：动态 K 与可再生猎物捕获反馈 — 离线候选 v2

## 来源与范围

- **已观测的 Unity 原始证据**：`TASK9_ACCEPTANCE_RESULT.json` 和 `task9-mushroom-formal.jsonl`；第429日鸡5525/菇狸267，第490日鸡1612/菇狸1814，第512日菇狸0。第490日鸡出生74、总死亡371、其中捕食死亡338 ⇒ **非捕食净补充 = 74-(371-338)=41只/日**，而捕食338只/日。此时捕食率反馈来得太晚。
- **源码确认**：`LandLifeRules.HuntLevel` 捕获需求来自猎手当天成年与理论出生能量缺口，由 `PreyDensityFactor(n)=n²/(n²+H²)` 反馈；此式没有明确的按日可再生捕获限额。`LandLifeRules.FoodCarryingCapacity` 已提供成年即期容量；旧 `EnvironmentalCarryingCapacity` 与真实付费出生的零增长容量不同。
- **本研究的假设**：通过限制*真实捕获量*、保留猎物恢复缓冲区，能让过量捕食者因真实食物不足减少出生/增加饥饿死亡。不增加食物，不强制扣人口；不更改原成年耗能0.40、出生压力0.80、捕食密度0.58或植物赛道70/30。

## 三个不同概念，不能混用

1. `AdultCoverage_i`（实测）：`min(1, adultPaid_i/adultDemand_i)`。吃饱不等于长期可持续。
2. `K_food,i`（现有试算）：固定其他种群与植物供给，使成年食物满足率≥99.9%的最大 `N_i`，不是零增长容量。不要再把旧 `environmentalK` 当成即时超载判决。
3. `K_eq,i(X_-i,R,traits)`（本候选）：在**当前其他食草种群暂时不变**、植物仅用可再生 R、不计捕食时，满足 `G0_i(K_eq)=0` 且 `G0` 从正跨至负的上侧根。`G0(n)` 用共享植物分配器、成年优先、真实产物成本、实际可支付的出生期望、成年自然/气候/饥饿与**已支付出生压力死亡**计算。不把今日 S 临时储量当永久收入。若无稳定根返回 UNKNOWN 并采用保守补给限额。它不是所有物种共同演化后的稳定种群数量。

## 数学候选（冻结给 Agent）

设 `N` 为捕猎前猎物数量，`G0(N)` 为该猎物在不受当天捕食影响时、可再生资源下的预测净人口补充，允许负值；`K_eq` 为该地块该猎物的条件零增长根：

```
N_refuge = 0.35 * K_eq
C_max = floor(clamp(G0(N) + (N - N_refuge)/45, 0, N))
C_actual = min(C_requested_from_original_HuntLevel, C_max_remaining_across_all_hunters_and_levels)
```

若 K_eq 无法求得，仅允许 `floor(max(0,G0(N)))` 作为上限，不凭空设置容量；若猎物已灭绝、没有 R、缺合法猎物，捕获为0。30–100日的恢复周期可进一步长期调优，但**本次默认锁定45**；refuge默认35%，在 Unity 验收前不改数值。低于 `N_refuge` 时恢复项为负，优先给猎物留下增长空间；高于时仅以45天周期释放多出的动物。当天已有多类猎手共用同一个限额，防止多个捕食层各自重复消耗。

**能量账本不变**：猎物只有发生真实`kills`才减少身体物质，猎手仅获得这些猎物的相应能量，损耗仍进入 detritus；猎手仍旧先支付成年消耗、再付款出生，资源不够自然减少繁殖并死亡。不能通过调小猎手人口的硬 K，不能额外创造或消除生物量。

## 验收边界

1. 旧模型 OFF：和历史输出逐日核对生态字段、环境字段与物质守恒；由于新增字段改变 canonical hash，允许仅模型配置 hash 不同，**绝不能**把生态内容差异解释为 hash 差异。
2. ON：针对 Task9 两条合法玩家路线、新物种首次出现、500日双方存活、人口趋势、原有不同种群群落、资源账本与真实时间开销；且反事实预测必须只读。
3. 独立对照：菇狸进化成功后停止后续负向植物操作 vs 原路线继续操作；必须记录两种情况下收益、风险及 K_eq/猎物配额。
4. 负面测试：无合法猎物、R降至零、R下降一半、起始猎物不足、多个捕食者分配同一猎物、L2吃L1不适用限制（明确报告而非冒充保护）。
5. 若高资源 3物种在 ON 分支长期捕食者过千，或其他生物数量失控，**FAIL/需要后续局部修正**；不得直接修改当前已冻结的其它 A+B+C+D 数值。
6. 性能：原5000日基线25.698秒，切ON需要对比，同硬件不能只看单次操作；目标不超过1.25倍，过慢标记 FAIL。新数值参数默认 OFF 直到用户审阅真实验收。
