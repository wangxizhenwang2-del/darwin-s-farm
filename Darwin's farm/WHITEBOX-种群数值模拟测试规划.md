# WhiteBox 种群数值模拟测试规划

从 `Assets/Scenes/WhiteBox.unity` 进入 Play，打开 **Darwin's Farm → 种群模拟器**，选择“连接游戏”。旧 `V41RegressionLab` 场景及其专用 Harness 已移除。本轮以数值模拟器的 **地块概览 · 趋势 · 每日输出 / 编辑与干预 / 导出测试数据** 三栏为测试入口。

## 一次测试怎样记录

1. 进入 Play 后先打开“导出测试数据”，填写测试编号、测试者，点击“开始记录”。保存为默认时间戳文件名 `Darwin_Whitebox_yyyyMMdd_HHmmss.jsonl`；每次运行只产生这一个文件。
2. 执行下面的用例。数值模拟器的环境、群落、固定变量、单格干预，以及游戏内环境科技和地图拓扑变化会记录操作；迁徙、分化、进化另有事件记录。对于这些入口以外的操作或视觉问题，填“操作/观察备注”，按“记录备注 / 检查点”。
3. 每做完一项，记录异常出现的模拟日、地块坐标、种群名和种群 ID，并截取对应 Game 视图画面。可以暂停后检查“地块概览”内的当前数据、趋势和每日输出。
4. 点击“完成并导出”，用“在资源管理器中显示文件”定位。退出 Play 前完成关闭；窗口关闭时也会自动刷新并关闭文件。回传 `.jsonl`，以及发生视觉问题时的截图/视频。无需上传文件夹。

文件每行是独立 JSON：`header` 包含场景、Unity 版本、测试编号；`action` 包含操作、来源、坐标、参数或拒绝原因；`transition` 包含迁徙/分化/进化的前后人数和 ID；`snapshot` 包含初始、成功操作后及每日结束时的全地图环境与存活种群。拒绝操作不重复采样。数据不采集逐帧鼠标坐标或摄像机移动，减少运行损耗。记录从点击“开始记录”开始，之前的操作不会补录。

## 用例顺序

| 编号 | 操作 | 重点核对 |
| --- | --- | --- |
| B01 基线 | 开始记录后先暂停，检查 Day、现有地块和种群，再手动推进 1 天 | 文件有 `header`、`initial snapshot`、`day_end snapshot`；当前数量、地形、温湿度、植物库存与窗口一致，无 Error/Exception。 |
| B02 编辑 | 在“编辑与干预”纵向检查环境、种群、固定变量、单格干预；修改一块地的环境，增添一个种群，再修改全局参数 | 四块内容无需内部分栏即可到达；提交成功有 `action` 和 `after_action snapshot`；未提交的草稿不改变 Model；现有种群编辑不误改数量。 |
| B03 环境 | 对一块陆地分别使用环境直接编辑和单格干预，推进到效果变化日；尝试一次无效值 | 温湿度、恢复量、库存、实时地形变化合理；成功与拒绝操作均可定位；拒绝操作不改变快照。 |
| B04 建造 | 在 Play 中放相邻地块，并通过已有入口改变高度 | 新地块/高度反映在 `action` 和下一次快照；原地块种群与资源没有无故重置。 |
| B05 食物网 | 选择有多个营养级的地块推进 20–50 天，观察捕食、出生、死亡和 K | 每日 `count`、`births`、`deaths`、`predationDeaths`、`k`、植物 `plantGrowth/plantConsumed` 连续可读；数量没有负数或突变成非有限值。 |
| B06 迁徙 | 用地块概览的“手动迁徙一次”按钮，再在启用自然迁徙后跨过迁徙日 | 有 `manual_migration action` 与 `Migration transition`；源地减少量、目标地新增/合并量与事件 `amount` 对得上；动画完成后视觉标签与模型一致。 |
| B07 进化与分化 | 启用相关固定变量，在合适地形持续推进，直到出现预设进化或生态位分化 | `PresetEvolution` / `NicheConversion transition` 记录源/结果 ID、新建或合并、人数；结果种群能在概览与后续日快照中追踪。随机事件若未出现，记录运行天数及参数，不当作自动通过。 |
| B08 时间与导出 | 暂停、继续、2 倍速、手动下一天，最后完成并导出 | `speed` / `next_day action` 与快照日序相符；输出只有一个时间戳 `.jsonl` 文件，最后一行可正常解析；空转时不发生逐帧文件写入。 |

## 回传时请附的简短说明

`测试编号 / 运行日期 / 相关 Git commit / 测试到 Day 几 / 哪个地块与种群 / 预期与实际差异 / 首次异常日 / 截图或视频名`。如无异常，写“未观察到异常”即可。我会根据 `action → transition → snapshot` 的顺序复盘数值与视觉，再提出具体修改建议。

## 性能核对

选同一场景、同一速度，各跑一段“未开始记录”和“正在记录”的模拟；记录 Unity Profiler 的主线程帧时间、GC 分配与导出文件大小。重点看每日结算瞬间是否出现额外卡顿。记录器只在每日结束、成功操作及关键事件时工作；若地块/种群数量显著增加，应再次做这项对比。
