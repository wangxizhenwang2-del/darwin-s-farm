## 本阶段发现和修正

1. 交付目录中的 `bioweb13.json` 曾由 LF 转为 CRLF，结构相同但 SHA-256 从规则要求的 `763fdd...` 变成 `0d09be...`；白盒启动时的运行时源图校验会因此失败。已从用户提供的 ZIP 恢复原始字节到 `Assets/Resources/V61Bioweb13.json` 和证据副本，并用项目根目录的路径专用 `.gitattributes` 禁止 Git 再次转换这两个文件。暂存区的 Git blob 与工作区原始文件字节一致。
2. 生态账本开账原先调用 `EnsureBodyMass`，会在读取余额时修改种群状态。现仅计算未初始化体质量的预计值，真实初始化仍由原有陆地日模拟负责。
3. 移除 `EnvironmentWorld.TryCancelRecovery` 中没有任何效果的循环，不改变取消规则。
4. 给环境与运动数学审计补充可复跑的 `.csproj`；隔离工作树的临时编译支持读取原工程生成的 Unity 项目文件和包引用，不修改正式工程依赖。
5. 复核发现已完成的陆地 R 操作会永久阻断后续生境变化的 R 自动目标。现在只在原生境保留捕获基线；之后生境变化会恢复新生境目标。新增回归用例先复现失败，修复后通过。
6. 邻地运动候选原先只把 `N/K` 概率乘进权重；单候选时仍必定变异。现用稳定事件随机数对候选做实际准入，之后与其他候选共用唯一席位。满五种且无同种的目标地也不再提供虚假机会，已有同种则允许迁徙合并。
7. 新加的迁徙人数硬裁剪使用当日 `carryingCapacity`，其数值不代表经过验证的反事实可接受容量。已回退这段新裁剪，保留原有目标容量概率修正；V6.1 的“实际允许不足 10 则取消”仍需建立可靠容量模型并通过实机验证，本阶段不宣称满足。
