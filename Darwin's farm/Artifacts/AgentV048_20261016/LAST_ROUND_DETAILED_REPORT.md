## 3. 代码实际改了什么

### 3.1 数据与物质账本

| 文件 | 上轮改动及作用 |
| --- | --- |
| `Assets/Scripts/BioData/PopulationData.cs` | 加入可稳定复现的种群身份/拆分序号、体物质，以及有时效的玩家压力、目标追踪、手动目标和三个策略性状的保护状态。 |
| `Assets/Scripts/BioData/BlockInfo.cs` | 增加地块腐屑物质池，用于承接死亡、缩小体型等释放的体物质。 |
| `Assets/Scripts/Simulation/LandLifeRules.cs` | 初始种群体物质只初始化一次；新生个体的体物质和幼体消耗一起进入食物需求；捕食从真实猎物体物质扣除并转移，死亡进入腐屑；资源不足时不能无偿增加动物体物质。当前默认单位体物质采用 `size × preyEnergyPerSize`。 |
| `Assets/Scripts/Simulation/SimulationController.cs`、`SimulationController.LandEvents.cs`、`SimulationController.Migration.cs` | 收获时按相同比例移除数量、体物质和储备；灭绝时把剩余物质归入腐屑；迁移拆分/合并携带对应体物质并复制目标与压力状态。日循环不再调用旧的同种本地拆分、同种合并与旧解锁。 |

这套账本通过的是**已进入日结模型的路径**。经济仓储/释放等其他入口的外部物质投入尚未完整纳入，不能据此声称全游戏所有入口严格守恒。

### 3.2 正式分化

在 `SimulationController.Evolution.cs` 中，把正式分化人数改成 `floor(母群数量 × 0.1 + 0.5)`，保留至少一只母群个体，不再把子群封顶为 100。提交前先做只读计划：检查目标资格、本地是否已有该物种、地块群数、可支付的目标体物质差额和目标食物供给。资源不足时可缩小实际子群；不足以生成至少一只时不改变原群。

提交分化时，母群保留当时五项实际性状；子群按目标物种模板设置五项初值。两群的旧玩家压力、目标追踪和保护状态分别清除，之后可独立接受新压力。子群新增的体物质从地块植物库存支付；若目标体型较小，释放的体物质进入腐屑。保留冷却和本地目标物种唯一性判定。

这里的“10%”是请求人数；真正落地人数还受食物和真实物质约束。真实 Unity 的 `formal-live-500` 夹具在第 5 天记录生成 54 只彩鸡，原因是当天母群数量已随前四天模拟变化，不能直接用最初 500 × 10% 推断第 5 天人数。

### 3.3 性状、玩家压力和目标保护

`SimulationController.LandTraits.cs` 将逐日选择整理为一个候选集合：温/湿适应倾向于地块当天实际温湿度；移动、体型和繁殖的自然候选要有正的模型预测增益与密度机会；成功部署的玩家技术提供独立压力，同方向可叠加权重。事件键控随机数从候选中只选**一个性状、一个方向、一步（±1）**，每群每天最多一次。没有候选时不改性状。

`SimulationController.Influence.cs` 保存玩家技术对种群的压力，按代码中的有效期和残余期衰减；提供自动/手动目标追踪；当移动、体型、繁殖进入目标容差区间时记录保护。持续下降且没有区间内补偿路径时，按进入保护的先后顺序每天最多释放一项保护；释放后在同一段区间内不立即重新附着。环境技术 Controller 只在真实部署成功后对受影响地块调用一次模型记录；温湿度、植物资源的物理环境效果仍走项目原控制器。

**重要差距：**规则要求自然策略具有长期正收益。当前 `ForecastLandGrowth` 是单日边际增长近似，并未做完整的 120/180 天前瞻。因此“候选为正”不等于长期生态稳定，这一项尚未达到规则的严格含义。

### 3.4 确定性与回放

新增 `SimulationController.Determinism.cs`：`ConfigureDeterministicRun(seed)` 在第 1 天前规范化初始种群身份、初始化体物质、排序模型状态；随机抽样由种子、日期、事件名、地块、种群等键组合生成，版本号 `DF-FNV64-1`；`CanonicalModelHash()` 用规范顺序和 SHA256 记录模型状态与调参。实际迁移路径也改用模型事件随机数，而不是 Unity 全局随机数。

新增 `Assets/Scripts/Simulation/Editor/V048ScenarioReplay.cs` 批处理回放器。它打开项目 WhiteBox 场景，进入 Play，暂停自动时钟，用真实地图预设和物种资源搭建输入，再通过真实 `EnvironmentTechnologyController.TryDeploy` 执行有序玩家操作，逐次调用 `clock.NextDay()`。JSONL 同时记录日模型哈希、环境轨迹哈希、玩家余额、植物库存、腐屑、每群数量/性状/出生/死亡/体物质等。回放头写入场景输入 SHA256、关键代码与资源绑定 SHA256、Unity 版本、种子和成本开关；操作行记录接受或拒绝及实际费用。日结时检查物质总量增加不能超过植物增长及浮点容差；拒绝操作会使整个场景返回失败，但仍保留追踪文件。

确定性成立的边界是**同一代码/资源版本、同一初始世界及配置、同一随机数种子、同一操作参数和同日顺序**。仅有“种子＋第 X 天在 (X,X) 操作 X”还不足以唯一确定输出。动作按 `day`、`sequence` 排序；动作在标明的那一天日结后提交，首个生态影响出现在次日。成本开关或操作失败同样会改变轨迹。

### 3.5 MVC 接口边界

主要变更在 BioData 与 Simulation 模型文件。Controller 只在成功部署环境技术后转交压力事件，并让收获调用物质感知的模型方法。旧的“定向进化立即修改两项 Bar”经济操作被明确拒绝，以免绕过每天一项 ±1 的规则。旧 UI 仍显示这项操作，上轮没有改 View；后续应由 UI 所有者同步移除或替换。上轮没有有意修改地图、场景、字体或序列化物种资产。

## 5. 未完成、已知风险和下一轮顺序

1. **长期选择规则未严格实现。**目前自然策略的“正收益”依据单日增长预测；应按新规则定义实现长期判定，先用固定场景比较旧/新候选与种群净变化，再复跑 R001、R002。不要通过硬调系数掩盖判定缺口。
2. **正常开局目标未达成。**R001 360 天无分化；R002 600 天无分化。鸡与浣熊约 5:1 的体验目标既未测成也未证明可达，需构造含两物种、实际资源与玩家预算的正式场景，并检查食物门槛、目标追踪和竞争结果。
3. **R002 正常费用序列无效。**需先设计玩家可支付的操作序列，或把不能支付明确作为该测试预期；不能拿关闭费用的轨迹声称玩家能在游戏里复现。
4. **全入口账本仍有旁路。**仓储、释放等经济操作对种群数据可能存在复制/再引入；需确认外部购买的物质来源、数量和记账，否则当前日结物质检查只能覆盖当前模拟路径。
5. **View 与旧功能入口未同步。**旧 UI 仍展示被禁止的立即定向改 Bar 操作。上轮遵守模型优先边界，没有擅改他人 View，但交付产品前需要协调处理。
6. **确定性结论有适用范围。**已验证若干同版本同输入的新 Unity 进程逐日重放。尚未验证跨 Unity 版本、不同平台、任意存档载入及所有控制器旁路。模型仍有未调用的旧 `FoodWeb.FeedCommunity` 等使用 Unity 全局随机数的代码，若未来重新接入日循环须重新审查。
