# V4.3 生态与 Visual 接入核查 · Handout

核查范围：当前工作区的 WhiteBox Scene、陆地环境与种群模拟、地块内队列移动、迁徙、生态位分化和预设物种进化。依据是代码与 Scene 序列化配置的静态检查；尚未在 Unity Play Mode 验证动画表现。策划规则参考 `游戏策划案v4.3.docx` 的迁徙、分化和 Visual 章节。

## 结论

**地块和生态模型已有基础连接；五种测试生物的数量、颜色和调试标签也连到了 WhiteBox。迁徙、分化、进化的数值变化尚未接入专门的视觉效果。** 当前视图通过每 0.25 秒扫描模型来增删种群方块、刷新数量，能看到最终结果，不能看到“分出一支、移动、抵达、合并或成为新种群”的过程。

| 链路 | 当前状态 | 证据与边界 |
| --- | --- | --- |
| 地块 → 生态 Block | 已接入 | `MapSimulationBridge` 在地块变化时建立 `BlockInfo`、四邻关系并交给模拟器；初始温湿度、植物量来自环境默认值。见 `Assets/Scripts/map/MapSimulationBridge.cs`。 |
| 环境 → 地块外观 | 已接入地形颜色 | `SimulationEnvironmentController` 把每日环境值写入 Block 并发布快照；`MapTileColorTransitionSystem` 在地形分类变化时刷新颜色。此处只确认颜色链路，不等于所有环境数值都有独立视觉反馈。 |
| 生态种群 → WhiteBox 方块与测试 UI | 测试接入 | `WhiteboxBiowebTestSetup` 为五种预设物种建视觉对象，按 `PopulationData` 对象引用同步数量，并赋各自颜色；调试 UI 读 Block 与种群数据，将种群文字锚在队列上方。未列入五种预设的派生物种不会获得方块视觉。 |
| 地块内移动、跟随、避障和玩家间距 | 视觉内部已实现 | `WhiteboxPopulation` 与 `PopulationTileSpace` 只在所属地块内选点、寻路和跟随；`PopulationMovementController` 处理对象间及玩家间距。运动状态没有回写生态模型，也没有跨地块路径。 |
| 陆地迁徙 → 过程动画 | 未接入 | `SimulationController` 会拆分、落地或合并，并触发 `OnPopulationMigrated`；运行时视觉没有订阅。下一次扫描只表现为源地数量减少、目标地数量增加或出现方块。 |
| 生态位分化 → 分支动画 | 未接入每日流程及视觉 | `ConvertNiche` 可从祖先拆出新 `PopulationData`、赋新 `speciesId` 并触发 `OnNicheConverted`；但海陆空入口尚未排进 `SimulateDay`，视觉也未订阅。 |
| 预设物种进化 → 新生种群动画 | 模型已接入，视觉未接入 | `ConvertToPresetSpecies` 从祖先拆出一部分，注册目标物种，并触发 `OnSpeciesEvolved`；WhiteBox 扫描后只会按目标物种显示新队列，或把人数并入既有目标种群，无分离/变色/出现过程。 |

WhiteBox Scene 当前序列化配置启用了迁徙和生态位开关；**开关为真不代表分化入口已进入每日流程**。`SimulateDay` 当前顺序是环境预更新 → 地块生态 → 预设进化 → 定期陆地迁徙 → 当日完成事件。水生生态及海陆空自动分化仍需单独接入。

## 三种效果应如何表现

| 变化 | 模型已做的事 | Visual 应做的事 |
| --- | --- | --- |
| 迁徙 | 原地扣除 `amount`，目标地新增或并入同种群 | 从源队列分出一支象征性的显示队列，跨地块走到目标；落地后出现目标队列或与既有队列合流。标签从权威模型读最终人数。 |
| 分化 | 祖先扣除一部分，建立**新派生种群**，生态位/物种标识不同 | 源队列分出一支，过渡到新颜色或形态；若目标地不同则移动过去，最终独立显示新种群。需给派生 `speciesId` 分配稳定颜色，不能只依赖五个预设 `SpeciesData`。 |
| 进化 | 祖先扣除一部分，生成目标预设物种的种群，可能并入同种居民 | 显示从祖先分离、变为目标物种外观，再独立注册显示或与目标种群合流。全局物种解锁提示可另做，但它不能代替这个地块内的新种群效果。 |

显示队列目前固定为四个方块，是数量的**象征表示**；分出的方块数不能直接解释为迁走的个体数。动画期间模型数值已经完成结算，Visual 只播放快照所描述的变化，结束后以模型为准校正人数和位置。

## MVC 接入方案

1. **Model**：`PopulationData`、`BlockInfo` 和环境世界保存真实状态；拆分、合并、注册及数量守恒继续由模拟规则完成。给每个活着的种群实例增加稳定的运行时 `PopulationId`。现有 `speciesId` 标识派生物种，`WhiteboxPopulation.UniqueId` 标识显示对象，都不等于模型种群实例 ID。
2. **Controller**：`SimulationController` 提交变化后发布只读的迁徙、分化、进化结果。每条结果至少带日期、源/目标地块、源/结果种群 ID、变动人数、结果是新建还是并入、结算后人数；分化另带新生态位和派生物种 ID，进化另带目标 `SpeciesData`。目前迁徙事件只传源/目标 Block、源种群引用和人数，缺少结果种群及合并信息；进化事件已传结果种群，但均无稳定 ID。让 Controller 将模型事件交给 Visual presenter，不由 View 决定迁徙或进化规则。
3. **View / Presenter**：把测试数据播种与种群显示绑定拆开。通用 presenter 订阅上述结果事件，按 `PopulationId` 管理 View、排队播放效果，并在 `OnDaySimulated` 或动画结束时用只读快照校正。`WhiteboxPopulation` 专管表现、队列运动和碰撞；测试 UI 专管文字。任何动画、碰撞或渲染回调都不修改 `PopulationData`。
4. **跨地块路径**：保留现有地块内漫游；另建跨地块过渡路径和到达交接。源地消失、目标地已有同种队列、目标地无法生成 View、途中地块被删除等情况，要有确定的视觉收尾，模型结算不等待动画。

## 实施与验收顺序

1. 先确立稳定种群 ID 和三类只读结果事件，记录一次变动的前后人数与合并目标。
2. 将 WhiteBox 的五物种播种留在测试脚本，把所有陆生 `PopulationData` 的显示绑定抽成通用 presenter，并为派生种配置确定性的颜色规则。
3. 实现“源队列分支 → 跨地块或原地变形 → 新建/合并”的统一过渡层，分别处理迁徙、分化、进化。
4. 将生态位分化的调度接入每日流程后再验收其自动效果；在此之前可通过现有公开入口单独演示，但不能称为自动接入。
5. 用空目标地、同种合并、源地迁空、原地进化、已有目标种群、无可用落点、途中地块改变等场景验收。每次核对源+目标的最终模型数量，并确认 View 最终与模型一致、动画未写模型。

> 静态核查的限制：以上确认的是代码调用和 Scene 配置，未执行 Unity Play Mode；队列与玩家碰撞的实际观感、跨地块寻路可行性及动态创建失败率仍需运行验证。
