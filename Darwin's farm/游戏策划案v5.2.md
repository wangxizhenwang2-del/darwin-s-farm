## 1. 世界、数据与地块

### 1.1 拓扑与生境

- **[冻结]** 地块为四边形；上下左右共享边才构成普通邻接。具体可达边取 `BlockInfo.neighbors` 与地图真实连接的交集，不因坐标对角相触就可迁徙。边界、河道和地形可使实际邻居少于四个。
- **[沿用]** 陆地海拔 `z∈{0,1,2}`。高差 0 平地、1 坡地、2 断壁。实际温度 `T`、湿度 `H` 是 0–100 的游戏指数，**不是摄氏度或相对湿度**。日植物恢复潜力 `R∈[0,150000]`，现存植物 `S∈[0,1000000]`，陆地容量 `B=1000000`。
- **[沿用]** 27 个陆地生境由 `z,T,H` 三者分类，映射八种视觉地形；`R,S` 改变不直接重分类。温湿三档为 `≤40`、`(40,60)`、`≥60`。地形变化重定默认环境目标，不应瞬间把实际环境或库存重置。
- **[沿用]** 水格有 Land、Across、Curved、Crossing、Lake 等形态与水道开口；相接水格须满足开口与海拔条件才合并水域库存。水格每格植物容量 150 万，默认 `R=75000`。水、空和跨生态位的完整生命循环仍需独立验收，不能用陆地五物种的结果推断已完成。

### 1.2 状态对象及身份

| 层次 | 必须记录 | 不得混淆 |
| --- | --- | --- |
| 地块 `b` | 坐标、形态、共享边连接、`z,T,H,R,S,B`、今日增长/消耗、碎屑 | 环境默认目标与实际值；物理库存与可分配预算 |
| 物种模板 | 物种 ID、五项默认性状、营养级、生态位、进化边、可捕猎物种 | 模板与当地种群实时性状 |
| 本地种群 `i,b` | 物种与谱系 ID、数量 `N`、五 Bar、身体物质、能量储备、小数余数、目标/保护/冷却 | 同种在不同地块是不同本地状态；迁徙不等于出生 |
| 全局物种 | 各地块同种数量之和 `N_s=Σ_b N_{s,b}` | 多个 population 不能算作多个物种 |

策划口径将植物称为 L0、食草动物 L1、捕食者 L2 及以上；现有 C# `trophicLevel==0` 表示食草**动物**，代码 1/2 表示更高动物级别。对账时必须写明映射，并用真实食物关系检查猎物，不能机械把代码营养级加一。

## 2. 玩家环境操作与时间线

### 2.1 五类合法科技

| 类别 | 正负档位与物理效果 | 最新时间规则 | 对性状的选择压力，而非直接赋值 |
| --- | --- | --- | --- |
| 植物存量 `S` | 当前剩余库存乘 `1±0.25` 或 `1±0.50`，裁剪到 `[0,B]`；`R` 不变 | 即时事务；不占持续槽；已执行交易不可回滚历史 | 增草偏向体型、繁殖；减草偏向小体型、运动 |
| 日恢复量 `R` | 目标相对当前合法基线增减 25000/50000，裁剪到 `[0,150000]`；`S` 不即刻改变 | **25 日进入、150 日维持、100 日恢复**；可撤销 | 增量偏向繁殖、可能压低运动；减量反向影响繁殖及体型 |
| 温度 `T` | 目标比当前生境默认值 ±25/50，裁剪到 `[0,100]` | 同上 | 长期适温适应；升温对体型有负向短期压力、降温相反 |
| 湿度 `H` | 目标比当前生境默认值 ±25/50，裁剪到 `[0,100]` | 同上 | 长期适湿适应；加湿对繁殖有正向短期压力、减湿相反 |
| 海拔 `z` | 每笔 ±1，越界拒绝；重算生境和邻接可达性 | 即时；不占持续槽；后续可再作合法反向操作 | 改变邻地可达性与生态选择，不直接改 Bar |

**[冻结]** 建立一个可达邻地后，目标地的气候、食物、居民拥挤和海拔连通性形成邻地吸引。通过目的地环境或高度修改可以增强、减弱或切断它；高差 2 即切断普通陆地迁徙。吸引信号应服务迁徙决策和运动能力的自然选择，但不产生“邻地吸引 +／−”的购买、占槽、撤销时间线。已有迁徙与性状变化不随邻地后来失效而倒带。

### 2.2 两槽、撤销和恢复

- **[沿用]** 每个陆格最多两个处于进入或维持的持续操作；第三个使最早占槽操作进入恢复。同通道重投应以提交时**实际值**重新起算，并明确覆盖旧命令。S、海拔及处于恢复阶段的操作不占槽。预览只读，提交时再校验合法性。
- **[冻结]** 持续操作在进入、维持或恢复的任一阶段均可请求撤销。撤销切断后续目标施压；从**当前实际环境值**按合法恢复过程回到对应生境基线，不跳回、也不倒带历史。恢复中重复撤销须幂等；反向新操作要明确替换关系，不能双计同日作用。
- **[冻结]** 已执行的 S 交易没有可撤销的持续 Buff。反向购买作用于现在尚存的库存，不赔还已被吃掉或已转成身体物质的份额。
- **[待验]** 温湿、R 分别做进入第 10 日撤销、维持中撤销、恢复中重复撤销、撤销后反向重投、跨地块互不干扰。记录每笔 `action_id,day,block,kind,tier,target,stage,cancelled_at,recovery_completed_at`。
- **[冲突]** 主工作区 `EnvironmentRules` 仍为温湿 25/150/150、R 即时后 50/50；Task 12 隔离工作树把常量调整为温湿和 R 的 25/150/100，并有局部 Unity 检查。两个代码位置不得混称为同一已合并版本。

### 2.3 时间与经济

环境时长以**模拟日**计算，与暂停、加速和实际每模拟日秒数分开。V5.0 WhiteBox 源码默认 `SimulationTime.DefaultSecondsPerDay=1`；v0.5 文字写 5 秒基础日但同时声明项目可配置值优先。V5.2 不据此推定正式体验常量已经冻结；每次回放应输出实际运行时 `SecondsPerDay`。Task 12 关闭玩家生物能、售价、收入、收割收益及科技货币付款；**植物、猎物、身体物质和新生儿的生态付款绝不关闭**。V5.0 的生物能经营、生态仓、收割和失败规则保留为更广义玩法设计，须另作经营系统验收。

## 4. 生态账本的统一记号与边界

`t` 是模拟日，`b` 是地块，`i` 是本地种群，`p` 是某种猎物。所有植物、生物身体、能量储备与碎屑以模型的生物量单位记，不把“只数”直接加到生物量上。

| 记号 | 单位及含义 |
| --- | --- |
| `N_i` | 当地活体只数，非负整数 |
| `S_b, R_b, B_b` | 植物现存生物量、当天实际恢复率、植物容量 |
| `G_b, P_b, C_b` | 今日实际再生、可领取植物预算、实际吃掉植物 |
| `Q_i` | 群体本日从合法植物/猎物获得的食物生物量 |
| `E_i` | 群体跨日已付款的食物储备 `energyReserve` |
| `M_i` | 群体活体身体生物量 `bodyBiomass` |
| `D_b` | 地块碎屑生物量 `detritusBiomass` |
| `s_i,m_i,f_i,T_i^*,H_i^*` | 体型、运动、繁殖、适温、适湿 |
| `F_i,A_i,Y_i,B_i^{new}` | 气候适应度、每只成年日维护、每只新生维护、每只新生身体物质 |
| `sat_i, K_i^{today}, K_i^{renew}` | 成年满足率、当日摄食尺度、可再生反事实容量 |

所有分母用有物理意义的正下界防零；所有账本项非负。`clamp(x,a,b)` 表示裁剪到 `[a,b]`，`ε` 仅用于浮点防零，不能凭 ε 生成真实动物或生物量。整数只数由对应余数累计后向下取整；任何被限制的未付款整只机会不得作为将来的免费出生债。

## 5. 每日结算顺序：以当前陆地代码为证据

**[源码]** `SimulationController.SimulateDay` 先发出 `OnBeforeDaySimulated`（环境控制器可能在这里推进环境日，必须核对订阅关系），再按确定顺序遍历地块。每块 `LandLifeRules.Simulate`，随后自然变异，刷新环境指标。全块结束后处理本地濒危注销、正式进化、达到迁徙间隔时的迁徙，最后刷新全体物种状态和各地块指标。`LandLifeRules.Simulate` 内部先长植物并初始化日账，再按代码营养级 2、1 捕食，接着给食草者分配并扣植物，随后逐群结算成年维护、出生、死亡、储备、身体和碎屑，最后更新历史。

因此同日观察须注明阶段：**当天捕食发生在食草分配和当天出生之前；正式进化、迁徙发生在当天生死结算之后；迁入对目标地的摄食份额主要从下一次地块生命结算起体现，但结算后指标必须立即重估。** 此顺序是当前陆地实现，不代表 V5.2 将来任何重构都可不经账本回归而改顺序。

## 6. 植物生产、可领取预算与同一库存竞争

### 6.1 真实植物存量

**[源码，默认参数]** 设日初植物 `S_t`、容量 `B`、当天实际恢复 `R_t`：

```text
G_t = min(max(0,R_t), max(0,B-S_t))
S_t^+ = min(B, S_t + G_t)
g = clamp(plantGrowthToday, 0, S_t^+)
V = max(0, S_t^+ - g)                           # 长在今天以前的现存量
L = R_t>0 ? min(0.10 B, 0.5 S_t^+) : 0         # 软库存保留；R=0 时可耗尽存量
W = R_t>0 ? min(max(0,V-L), 0.10 V) : V          # 本日可抽老库存
P_t = max(0, min(S_t^+-L, g+W))                 # 所有食草群共享的唯一预算
C_t = sum_i allocatedPlant_i,  0≤C_t≤P_t
S_{t+1}^{feeding} = S_t^+ - C_t
```

`G_t` 是真实进入世界的植物生物量；`P_t` 是本日最多能被取走的部分，**不是另一份库存**。`R=0` 可暂时消耗遗留 `S`，却不能将存量解释为永久日再生。若当日有玩家 S 事务或正式进化的植物补差付款，按交易发生阶段继续从实际 `S` 扣减，不能从 `P` 再扣一次。

### 6.2 采食效率及分配器

**[源码]** 气候适应与成年需求分别为：

```text
F_i = clamp(1-(|T_b-T_i^*|+|H_b-H_i^*|)/90, 0, 1)
A_i = adultMaintenanceScale × (max(0,s_i)+200/max(1,s_i))
      × [1+0.4×(clamp(m_i,0,100)/100)^2]
adultNeed_i = N_i × A_i
```

默认 `adultMaintenanceScale=1`；V5.1 的 `0.40` 是实验候选，不能混进默认曲线。体型增加通常增加绝对维护；非常小的体型有 `200/s` 额外成本；高运动也有能耗。`F_i` 只描述温湿吻合，不是完整净增长率。

当前觅食可达性及两个虚拟植物通道的效率：

```text
reach_i = forageSizeScale/(forageSizeScale+max(1,s_i))
mobility_i = 1+clamp(m_i,0,100)/forageMovementScale
accessBase_i = clamp(1-forageAccessLossAtZero×reach_i/mobility_i²,0,1)
common_i = F_i × accessBase_i × (1+movementForagingGain×m_i)
x_small = max(1,s_i)/smallPlantSizeScale
eff_small = 1/(1+x_small⁴)
x_large = max(1,s_i)/largePlantSizeScale
eff_large = x_large⁴/(1+x_large⁴)
```

默认 `forageSizeScale=20`、`forageMovementScale=10`、`forageAccessLossAtZero=.08`、`movementForagingGain=.002`、`smallPlantSizeScale=20`、`largePlantSizeScale=25`。群体的偏好通道由分支策略/模板决定；跨通道效率再乘 `unspecializedPlantEfficiency=.7`。默认**未启用 70/30 优先预算开关**时，两个通道的加权效率合成为 `access_i`，在唯一预算 `P` 上迭代分配：

```text
adultNeed_i = N_i A_i
birthNeed_i = N_i × birthRate × (f_i/100) × F_i × (Y_i+B_i^{new})
unmet_i = max(0, need_i-received_i)
weight_i = access_i × unmet_i
proposal_i = min(unmet_i, remainingBudget × weight_i / Σ_j weight_j)
```

先对**全部群体的成年需求**迭代，吃饱者退出并重分配未领预算；然后才对潜在出生需求执行同一算法。分配次序须不影响结果，`Σ_i allocatedPlant_i≤P` 且任何群不超过真实未满足需求。`birthNeed` 是分配阶段的潜在请求，绝不等于实际已出生数。

**[候选 V5.1 C]** 启用 `enablePriorityPlantBudgets` 时，仍只有一份物理 `P`，先临时设 `P_small=.70P`、`P_large=.30P`；两偏好群的成年请求先在各自通道分配，再将未用份额交给另一群；完成全部成年后才以剩余预算处理出生请求。可流转余额只准使用一次。70/30 是虚拟**优先顺序**，不能创建两个可独立增长、结余的 `S`。

### 6.3 反事实摄食与竞争者

任何单群净收益或 `K_food` 预测都应使用与真实日分配一致的竞争器，在固定其他群 `N_j` 下代入候选性状或候选数量，再从唯一 `R_eff` 预算分配。竞争者迁入、死亡、进化或改变体型都须重算；仅用 `R/每只需求` 忽略现有竞争者会高估目标种容量。

## 7. 捕食、猎物可持续性和身体转账

### 7.1 合法关系与单次捕获

**[冻结]** 捕食者只可吃当前食物网明确允许的物种；菇狸只吃鸡和彩鸡，孔雀吃鸡。当前 `FoodWeb.CanEat` 在捕食者资产的 `preySpecies` 为空时存在按营养级放行的回退逻辑，因此“只走白名单”必须作为验收断言，而不是仅凭设计文本认为源码已完全满足。

**[源码]** 对合法捕食者 `h` 与猎物 `p`：

```text
chase = clamp(1+(m_h-m_p)/40, .1, 1.5)
sizeFactor = clamp(((s_h+10)/(s_p+10))², .1, 1.5)
captureChance = clamp(.5 × chase × sizeFactor, 0, 1)
attackAccess = min(1, 10/max(1,s_p))
preyEnergyPerKill = (M_p/N_p) × min(1,s_h/(s_p+15))
huntPreference = attackAccess × captureChance × preyEnergyPerKill
```

基础捕获率 `.5`、追赶尺度 `40`、身体系数 `40×s` 为当前调参默认。真正的捕食意向会按猎手对所有合法猎物的 `huntPreference` 归一化，再乘猎手人数、接触机会、捕获率和可选的猎物密度因子；多猎手索取要竞争，不能每名猎手对同一猎物各自独占全部库存。

猎物活体数量扣 `k`，同时从猎物活体身体账扣 `M_removed = M_p_before×k/N_p_before`；可捕获的那一部分转到猎手今日猎食能量/储备，未利用身体进碎屑：

```text
N_p_after = N_p_before-k
M_p_after = M_p_before-M_removed
Σ_h energyFromThisKill_h + detritusFromKill = M_removed
0≤k≤N_p_before
```

捕食死亡只记一次。小数捕获余数只保留分数，不能把因配额禁止的整只捕获积成下一日“复仇债”。

### 7.2 V5.1 候选与 Task 10 配额

**[候选 V5.1 A]** 食草猎物密度反馈开关 `enablePreyDensityFeedback` 打开时：

```text
H_p = max(1, 0.58 × R_ref/max(ε,A_p))
F_density(N_p) = N_p²/(N_p²+H_p²)
```

`R_ref` 须取已定义的场景参考恢复量；猎物变少则遭遇率降低。该半饱和式当前只给食草猎物提供稳定植物生产参照，不能未经推导直接推广到捕食性猎物。默认开关和序列化场景值须逐次记录。

**[候选 Task 10]** 另一个默认关闭的 `enableDynamicPreyRenewalQuota` 对代码营养级 0 猎物估计无捕食净更新 `g_p(N)`，寻找条件平衡 `N_eq`，再算：

```text
buffer_p = 有平衡 ? (N_p-0.35 N_eq)/max(10,45) : 0
quota_p = floor(clamp(max(0,g_p(N_p)+buffer_p), 0, N_p))
actualKills_p ≤ quota_p
```

当猎物低于恢复庇护水平时，`buffer` 为负，有利于恢复。`quota` 是当日**猎物可消耗只数配额**，不是 K，也不是独立发生的真实捕食次数。已有局部验收仅证明被启用的 L0 夹具无超额；L1 猎物、所有物种与完整迁徙耦合尚不能宣称通过。

## 8. 出生、死亡、储备与身体质量

### 8.1 新生儿完整付款

**[源码默认]** 新生儿维护和身体付款：

```text
Y_i = .4 s_i + .02 s_i²
B_i^{new} = 40×max(1,s_i)
CostNewborn_i = Y_i+B_i^{new}
```

`B_i^{new}` 是从食物转入新活体身体的物质，不是消耗后再凭空创建。运动／体型变更导致的既有身体质量差异，也须单独记转账或汇，不能静默改写总质量。

### 8.2 本日出生机会与整数结算

**[源码]** 捕食后仍活的只数为 `n_i`，本日植物摄食或猎物取得的食物加上已有合法储备构成 `available_i`：

```text
adultDemand_i = n_i×A_i
sat_i = adultDemand_i>0 ? clamp(available_i/adultDemand_i,0,1) : 1
opportunity_i = n_i×birthRate×(f_i/100)×F_i×sat_i
possible_i = floor(birthRemainder_i+opportunity_i)
birthBudget_i = max(0, available_i-adultDemand_i)
born_i = min(possible_i, floor(birthBudget_i/CostNewborn_i))
```

默认 `birthRate=.1`。支付顺序：实际成年付款 `min(available,adultDemand)`，然后 `born×CostNewborn`，剩余合法资源才可结转储备，储备上限为 `adultDemand×reserveDays`（默认 10 日）。实际出生不允许超过整数机会、食物或身体付款能力。生育余数最后裁到 `[0,.999]`，不能积存未付款**整只**机会。小种群 `N=1,2,9,10` 必须既可能随时间积累合理出生概率，又不出现免费新生儿。

### 8.3 死亡及生育压力

默认自然死亡期望值按项记账：

```text
D_starve = .6 n_i (1-sat_i)
D_cold = .005 n_i × max(0,(50-T_b)/50)
D_climate = .01 n_i(1-F_i)
D_base = n_i × [.008×20/(20+max(1,s_i))
                  + .5/(1+max(1,s_i))²]
D_natural_expected = D_starve+D_cold+D_climate+D_base+D_birthStress
```

旧式生育压力依据连续的“预期已实现出生”估算。**[已确认方向／候选参数]** 付费出生方案要求 `born=0 ⇒ D_birthStress=0`，并用 `born×stressCoefficient×clamp(f_i/100)×Y_i/max(1,s_i)`。源码 `enablePaidBirthStress` 才走此路径；默认系数为 1.2，V5.1 提议 0.8，仍须分别验收，不得说二者已正式默认。饥饿、寒冷、气候失配和基础成年死亡不随“没有出生”一起消失。

自然死亡小数余数累计后取整，但最多扣当前活体；灭绝不留下将来误杀迁入者的死亡债。死亡活体身体转入碎屑。若 `count` 是当天捕食后、出生前的只数：

```text
died_i = min(count, floor(deathRemainder_i + D_natural_expected))
N_i^{afterLife} = count + born_i - died_i
M_i^{afterLife} = M_i^{afterHunt}
                  - M_i^{afterHunt}×died_i/count
                  + born_i×B_i^{new}
```

`count=0` 时身体死亡项定义为 0。出生、自然死亡、捕食死亡、正式进化转出和迁移转入转出在日志中分别列列；只看 `N_end-N_start` 不能归因。

### 8.4 能量储备和日汇

储备只包含过去从真实植物或猎物取得且未花完的资源。逐群要满足以下收支形式（留意捕食者当日猎获先进入 `E` 再用于当日分配）：

```text
合法期初储备 + 本日合法摄食/猎获
 = 实付成年维护 + 实付新生维护
   + 转入新生身体 + 合法期末储备 + 溢出/代谢等有名汇
```

源码另记 `accountedBiomassSinkToday`；它是待与植物、猎物、身体、储备、碎屑核对的汇记录，不代表忽略的差额可随意消失。精确日账应以实际事件和实际值重建，而非依一个汇字段宣称全世界守恒。

## 9. 三类容量、动态 K 与 `N/K` 的正确作用

| 指标 | 定义／公式 | 正确用途与限制 |
| --- | --- | --- |
| `K_today`，源码 `carryingCapacity` | `allocatedBiomass_i/A_i` | 当天该群实际领取食物相当于多少成年个体的维护。受本日总需求封顶，不是长期承载极限。 |
| 旧 `environmentalK` | 食草者以 `R×小/大通道份额×效率−同通道竞争者需求` 除 `A_i`，取非负；捕食者以可持续猎物能量估算 | 当前默认分化选择可能仍用它；可能漏掉跨通道竞争、短期和长期差异。 |
| `K_food`（食草） | 固定其他群，以 `R_eff=min(max(0,R),B×[1−min(.5,reserveFraction)])` 反复调用**同一植物成年分配器**，二分最大 `n` 使 `allocatedAdult_i(n)≥nA_i` | 只读反事实，不消耗今日 S；仅当显式开关接入选择才改变进化路径。 |
| `K_food`（捕食者） | 以猎物历史 `max(0,平均出生−非捕食死亡)`、合法猎物、相遇机会、竞争猎手份额推求满足成年维护的最大 `n` | 只读条件预测，猎物存量/更新为零时应趋零；尚非已证实长期稳态。 |
| `K_eff` | 在可持续更新、竞争、捕食与人口反馈下长期净增长约零的条件容量 | 设计目标；不能用单日 `K_today` 或一次离线平衡冒称已求得。 |

**[冻结]** `K` 不剪裁活体数量。允许 `N>K`，由后续食物不足、出生下降、死亡、生态位变异或真实迁出表现负反馈；不得瞬间删减多余个体。环境变化、草供给变化、猎物变化、进化、迁入迁出后须在一致时序重估 K。捕食者 K 尤其不能把猎物身体**存量**当无限可再生供应。

当前变异代码以 `ratio=N/environmentalK`（当 K≤0 时置 1）给自然运动/体型/繁殖候选机会：

```text
p_natural = 0.5-0.495×clamp((N/K)/0.95,0,1)
```

故最低仍约 `.005`，不是绝对零。候选还须预测收益高于 `mutationGainThreshold`。需要验证此旧 K 输入是否会在彩鸡与母鸡竞争、菇狸猎物稀缺或迁入后误抑制**有正收益**的补偿；仅观察到 `N/K` 高不能证明该机制是失稳根因。

## 10. 五 Bar 变异、引导、目标与保护

### 10.1 单一变异席位

**[冻结]** 每群每天最多一次变异机会，胜出者仅改一项性状 ±1。适温、适湿向长期实际气候靠齐；它们不享受短期性状收益/保护，并与运动、体型、繁殖共享机会，按规则需有气候优先竞争。运动/体型/繁殖的自然候选须比较当下与候选**全群**预期净增长，含真实竞争与捕食风险；正收益阈值以运行时配置记录。

当前源码先对温湿差生成候选，再对运动/体型/繁殖的 ±1 用 `ForecastLandGrowth(candidate)-ForecastLandGrowth(current)` 做收益筛选，同时加入近期玩家引导候选；所有正权重候选汇总后一次抽取。这里的**加权候选并不等于温湿绝对优先**，须与冻结规则对照测试。`ForecastLandGrowth` 是预测评分，不直接付款或出生。

### 10.2 玩家引导与保护状态机

合法科技事务成功后，当前实现向本地现存群体写方向影响；源码默认引导 7 日、残余 5 日，仅是本版实现参数。S/R 的正负、温湿变化对运动/体型/繁殖的权重见 `SimulationController.Influence.cs`；成功引导仍只参加以后每天的一次候选选择，不得立即改 Bar。邻地机会当前可经 `ReadLandSelectionSignals` 计算，但 `EvolveCommunityNewRules` 未读取该结果构造运动候选，是**已定位接线缺口**，不能用迁徙概率已有邻地项冒充运动变异已接入。

**[冻结保护语义]**

1. 近期合法引导在有效期内避免刚获得的方向收益立刻被相反选择抹掉；撤销后不再施加新压力，已产生保护/残余逐渐失效。
2. 自动追踪合法且本地尚不存在的最近可达进化目标；如玩家在允许的玩法中指定合法目标，须仍受进化边和本地存在性校验。目标切换应重置与旧目标关联的保护，而不是直接改性状。
3. 运动、体型、繁殖分别进入目标容差后，可阻止随后一个 ±1 候选**离开目标容差**；适温、适湿不受这种短期保护。五 Bar 全达标的保护、优先级和有效期须作为独立规则检查，不能把三个数组字段直接当成完整“三重保护”已验收。
4. 当近 10 日平均增长显著为负，且受保护区内没有正收益补偿方向时，最多按进入顺序解除一项最早保护；不能让保护永久强迫群体走向灭绝。当前源码阈值约 `−0.01`，具体是否合适须对照生态日志，而非硬改物种特例。
5. 正式进化时母、子群旧影响、追踪、保护和未结算变异状态按事件规则清理；物理环境若还在持续或恢复，继续按地块时间线运行，不因个体状态清除而跳回原值。

## 11. 普通分化、正式物种进化与付款

### 11.1 普通本地分化

**[沿用／待验]** 旧规则以 `N>200`、最近 10 日平均满足率至少 `.95`、`N≥.9K_selection`、冷却、空间、库存及分支后食物支持等判断是否产生普通本地分支。默认分出 `5%`，新支运动/体型/繁殖曾按目标方向重置一定比例并锁 50 日，温湿继续自然适应。同种分支超过约 100 日仍未转成不同物种，可按真实数量、性状、物质加权合并，合并后有约 200 日本地分化冷却。**当前 `IsDirectedTraitLocked` 固定返回 `false`，不能称 50 日锁已生效。** 普通分化 5% 不得全局改成正式进化的 10%。

### 11.2 四次正式进化

**[冻结]** 只有当前图上的合法相邻物种边、五项性状均在目标容差、连续合格日、合法地块/生态位、食物支持、付款、冷却和本地目标未存在时才可转换。当前源码默认容差 `±5`、合格连续 5 日（地块已有四群时 10 日）、今日食物满足 `.9`、可再生满足 `.8`；这些是**实现配置**，应随运行导出，不能当永远冻结的策划常数。

当前正式计划数采用四舍五入式近似：

```text
requested = min(N_source−1, floor(0.10 N_source+0.5))
sourceBodyPerHead = M_source/N_source
targetBodyPerHead = 40×max(1,targetSize)
extraPerHead = max(0,targetBodyPerHead-sourceBodyPerHead)
affordable = extraPerHead>0 ? floor(spendablePlant/extraPerHead) : requested
newTargetCount = min(requested,affordable)
plantPayment = newTargetCount×extraPerHead
excessBodyToDetritus = newTargetCount×max(0,sourceBodyPerHead-targetBodyPerHead)
```

`newTargetCount≥1` 才提交；母群扣相同只数，子群使用**目标物种模板默认五 Bar**，按目标体型登记新身体。付款来自真实剩余植物 S，原身体比目标身体重的多余部分转碎屑；人数与物质均不可凭空生成。实验性的 `useCompensatedEvolutionFoodGate` 若启用，会先保护一部分库存并做更严格的生态补偿预测；默认旧存档不开。正式进化绝不使用迁徙单次最多 100 只限制。本地已有目标种拒绝重复生成；另一地块有目标种本身不应无端阻断本地合法事件。

## 12. 真实迁徙与邻地机会

### 12.1 可达、概率与数量

**[冻结]** 目的地必须是共享边相连的合法陆地，且高度差 ≤1；高差 2 或无连接一律拒绝。自然迁徙默认约每 7 日检查一次；平地运动 `>30`，一级坡 `>60`。目标地食物、气候连续性、猎物、居民拥挤与冷却决定是否值得迁徙。迁徙不是出生，不能为凑事件数直接瞬移。

当前源码的邻地吸引与成功概率为：

```text
freeFood = 目的地植物剩余供给或合法可持续猎物食物，扣除居民需求
adultDemandMigrants = proposedMigrants×A_i
climateContinuity = 1−.2×|T_source−T_target|/100
                      −.2×|H_source−H_target|/100
attraction = clamp(freeFood/(freeFood+adultDemandMigrants)
                   ×max(0,climateContinuity)×F_i(target),0,1)
targetCapacityCorrection = clamp(1−sameSpeciesResidents/estimatedTargetCapacity,0,1)
p_success = attraction×(m_i/100)×targetCapacityCorrection
```

地块已有四个群落时，当前实现再乘 `fourEntryMigrationFactor=.5`；最终不能超过社区槽位。上述是**当前算法**，不是“额外邻地吸引按钮”。高差 1 的代码可达性门槛明确；若设计还要求独立坡地概率惩罚，须核对当前运行路径是否实际应用，不能凭常量名字宣称已存在。

```text
naturalMigrants = N<10 ? 0 : min(N, clamp(round(0.10 N),10,100))
```

实际迁移仍须满足冷却、目标容量和随机接受。标准 100 只上限只属于迁徙；正式进化从母群 10% 计算。高度操作可使邻地从可达到断连；目标地生态适宜度和实际自由食物会改变吸引程度。

### 12.2 原地与目的地结算

自然计划先统一选出，再**全部从源地拆离，随后统一落地**，阻止新来群在同一天再次链式迁徙。已有同种居民则合并，基因/性状、身体物质、储备、余数和冷却必须按可追溯规则处理；目的地最终无容量时应退回并恢复原账。迁入后源、目标地立即刷新生态指标，下个生命日用更新后的竞争份额摄食。

单条迁徙事件应满足：

```text
N_source_after = N_source_before − migrants
N_target_after = N_target_before + migrants     # 包括同种合并
ΔΣ_b N_species | 只看这条迁徙 = 0
```

完整游戏日还须加减出生、自然死亡、捕食、正式进化与濒危注销。若某代码路径在合并时改变体型、储备或身体物质，须把加权及多余物质去向写到账本。V5.0 曾排除已有同种居民作为**自然**迁徙目标；较新的 v0.5 要求验证真实同种迁入合并，当前源码也可处理此情况，不能沿用旧文把合并情形一律禁止。

## 13. 全世界每日守恒式与审计事件

### 13.1 物质账

设 `W_t=Σ_b[S_b+D_b]+Σ_i[M_i+E_i]`，另把水域库存、其他已接入资源及仓库按实际模型列入；`Input_t` 是实际植物生长、合法玩家增加库存等外源投入；`Output_t` 是成年代谢、新生维护、库存溢出、合法减少库存、系统明确记为汇的部分。则每天应有：

```text
W_{t+1} − W_t = Input_t − Output_t + numericalResidual_t
```

捕食、出生身体转入、普通分化、正式进化、迁徙、同种合并都是系统**内部转账**，各自不得成为未说明的 `Input`。死亡身体通常由活体转碎屑；有碎屑腐解机制时再单列其流出。每个日结算给出绝对残差、相对残差和允许的浮点容差；不能用“曲线看起来稳定”替代守恒验收。

### 13.2 人数账

对每种 `s` 的全局人数，分别记四种转移：

```text
N_s(t+1) = N_s(t) + paidBirths_s − naturalDeaths_s − predationDeaths_s
           + formalEvolutionIn_s − formalEvolutionOut_s
           + otherExplicitConversionsIn_s − otherExplicitConversionsOut_s
           − legitimateEndangeredRemoval_s
```

同一世界内迁入和迁出在全局和中相消；若它们改变全局同种数量就是 bug 或混入了生死事件。各本地群再单列 `migrationIn/migrationOut`。普通同种分化与同种合并只改群体结构，正常不改该物种全局只数。正式进化总动物只数也守恒，但物种间转移 `N`，且可能需要额外身体生物量付款。

### 13.3 最低逐日日志模式

每地块：`day,seed,block,neighbors,z,T,H,R,S_start,G,plantBudget,plantConsumed,S_end,detritus,stockAction,evolutionPlantPayment,environmentStage`。每群：`speciesId,lineageId,N_start,predationDeaths,plant/animalFood,adultNeed,adultPaid,birthOpportunity,born,newbornCost,birthStress,naturalDeaths,N_afterLife,formalOut/formalIn,migrationOut/migrationIn,N_end,bodyStart/bodyEnd,reserveStart/reserveEnd,F,sat,K_today,environmentalK,K_food,target,protectionState`。事件表另有 `day,from,to,amount,before/after,reason,cooldown,capacity,resourcePayment`。同 seed、同操作、同配置须产生相同关键事件与逐日哈希。

## 14. Task 12 分级验收与当前证据界限

1. **A–D 基线**：单鸡、竞争、捕食、富资源出生、猎物配额、确定性与物质账；任何新机制均不得暗中破坏。

3. **迁徙机制**：2–4 个真实相连四边形地块测平地、坡地、断壁、斜角、拥挤、冷却、少于 10 只、100 只封顶、同种合并及人数/身体守恒。综合世界至少两次有真实生态原因的成功迁徙，另有一次合并及一次合法拒绝机制证据；不要求 20 次。
4. **逐级生态**：先二种，再三、四、五种；每一阶段追踪食物份额、捕食、K、资源与保护，不准一个大场景只看终点物种名字。

6. **自然共存**：第五种产生后，等最后玩家操作和全部持续效果恢复完，从三者最晚日开始至少 1000 日无新干预；五种全程 `N_s>0`，最后 500 日各 `N_s≥10`，最后 200 日检查趋势、振幅、植物库存、猎物更新与捕食者有界性。活着不自动等于稳态。
7. **多种子与重放**：固定 240、241、242 使用同一地图、公式和可观察状态政策；三种子都过才能报完整通过，单个只报单种子通过。同种子至少复跑一次核哈希。离线计算仅作为候选评估，不得冒称 Unity 验收。

## 附录 D：两条目标路线的可操作研究边界

玩家能合法改变 `S,R,T,H,z` 和地图真实连接，因而可依观察到的性状、资源、保护状态和目标门槛，分阶段改变选择压力：先令鸡满足彩鸡目标，再令彩鸡满足孔雀目标；另保留鸡母群，用适合菇狸目标的环境推进鸡→菇狸，再令菇狸满足鹿目标。可达邻地及海拔差能改变迁徙机会和理论上的运动压力；必须用每日日志确定各群真实五 Bar 是否朝目标移动。**这里是研究政策空间，不是已证明稳定触发操作表。**
