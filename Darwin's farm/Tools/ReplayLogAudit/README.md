# 多人测试日志校验（v4）

1. 所有测试者使用同一份工程版本及 Whitebox 场景。场景中的 `WhiteboxBiowebTestSetup.replaySeed` 设成相同整数，保存场景后再分发工程。
2. 进入 Play 模式，待初始种群出现后，在“生物模拟器”窗口点“开始测试（选择导出文件）”。测试结束点“提前结束记录并导出”，或者退出 Play 模式自动导出。
3. 收集完整的 `.jsonl` 文件，在工程目录运行：

   ```powershell
   python Tools/ReplayLogAudit/verify.py "tester-a.jsonl" "tester-b.jsonl"
   ```

脚本先验证每个文件的 `logSha256`。相同的 `input` 表示场景、版本、种子、初始快照和有序操作相同。只有这组相同的输入才比较结果；`MATCH` 表示每日/操作后快照及生态事件相同，`DIVERGED` 会给出第一条不同记录与字段。`result` 是编辑器写入的复现确认码，包含输入和结果。备注、测试者、时间戳和速度不会改变复现确认码。

要在 Unity 内重放：重新进入同一 Whitebox 场景的 Play 模式，等初始种群出现，打开“生物模拟器”，点“在当前 Play 场景重放日志”，选择完整日志。入口先核对工程/场景/种子和初始快照，再按日志顺序执行操作和推进天数；第一个不同的快照会显示 Day、原因、模型哈希和生物能。它会暂停时钟，重放后保持暂停以便查看。对于无法识别的操作会停止并报告，不会跳过成功操作。

重放覆盖生物模拟器窗口、环境科技和玩家经济控制器提交的成功操作。地图事件作为结果观察记录在原始日志中；直接从调试脚本调用地图底层 API 不属于玩家操作入口。

复现出现分歧时，先看首个不同的操作后快照或日终快照。操作在同一天内的**顺序**也属于输入，仅有“天数 + 坐标 + 操作名称 + 种子”不足以唯一决定结果；还需要操作的完整参数、初始状态和规则版本。
