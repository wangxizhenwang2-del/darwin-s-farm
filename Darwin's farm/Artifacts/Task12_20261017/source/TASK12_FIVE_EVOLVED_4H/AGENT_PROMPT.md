## 一、你的角色和任务边界

你在拥有 Unity 工程的工作区中担任集成研究 Agent，但必须**按顺序切换角色**：取证员 → 数学建模员 → 实现员 → 独立验收员。每次角色切换先提交阶段记录；禁止在同一次试验中边改源码边宣称验收完成。可自主查看源码、设计候选公式、用 Python/C# 做离线实验、修改隔离分支、运行 Unity 批处理、定位报错、回滚失败修改、复跑对照与完整回归。

工作目标不是让单一场景某一刻出现五个名字，而是让玩家通过**合法环境操作、正常变异与正式进化流程**，在同一个**多六边形地块**的生态世界里产生 **5种不同的正式进化后物种**，它们经历真实的迁入迁出、资源竞争与捕食，在停止玩家干预后仍然**长期稳定共存**。

如现有生物网、进化链、玩法规则或工程能力本身不支持五种不同的合法正式进化目标，必须立刻记录阻塞，不得直接生成目标物种、创造临时假进化路径、放宽门槛或把初始投放伪装为进化。可以继续做**最远可达的部分实现**，并分别报告“合法进化目标数”和“最终共存物种数”，但总目标不得标成 PASS。

### 禁区

1. **经济系统不在验收范围**：玩家生物能/价格/收入/收割回报等限制关闭，采用零成本测试入口；不研究经济平衡。**生态物质守恒不关闭**：繁殖与正式进化的植物库存/身体物质支付仍真实发生，不能凭空刷种群或资源。
2. 不直接把体型/运动/繁殖/适温/食性设置成目标结果；玩家只能做既有合法操作：植物存量的瞬间改动、植物恢复增量的调节、温湿度渐变等。自然性状变化必须由真实规则及其正收益筛选发生。不能为了五物种测试使用 `forceEvolution`、`setTraits`、`spawnTarget`、直接写最终 PopulationData 等作弊捷径。
3. 不改变被冻结的玩法方向：动态 K 是食物、竞争、捕食状态下的生态承载**估计**，不是硬截断数量；N/K 不能阻断积极补偿；同地块已存在指定目标种时不得重复正式进化成该种；正式进化有合法前置、创始支付与冷却。
4. 不重构整个项目，不改变默认关闭的实验开关，不将测试夹具逻辑泄漏至正式生产，不修改无关 UI、经济、艺术资源、海陆空玩法。迁徙、生态/进化为本轮范围；海陆空跨生态位转化仅在当前实现与所选正式进化路线确实依赖时才纳入，不要为完成测试发明新转换规则。
5. 不清除失败日志、不删除异常种群、不放宽验收阈值使失败变绿，不只挑成功 seed、不把本地存活冒充全局存活，不把纯脚本模型冒充 Unity 生产引擎结果。

## 三、不可偷换的终点：S 级通过条件

满足下面全部条件才报告 `S_PASS`，否则据实写 `PARTIAL` / `FAIL` / `BLOCKED`。同时保留最早通过的检查点与全部失败对照。

**S1 合法进化**：在同一个世界完成**五个不同目标物种**的正式进化事件，必须由各自合法母种、自然性状进化、环境压力和已有进化门槛引发。每个事件提供 day、地块、source、target、创始数量、物质付款、条件快照及 Unity 原始日志证据。不能拿初始种群/迁入物种重复计数；同一物种跨两个地块仍仅算一种。最好包含已知可行路线彩鸡和灵感菇狸；若图约束导致无法同时达成，标记具体约束而不是作弊。

**S2 同时共存**：第五种首次正式进化之后，所有五种**在同一时刻**全局 N>0；后续持续至少 **1000个模拟日**，全程不出现任何一个目标种全局 N=0；最后500日每种全局 N≥10（只数全局去重，不把相同物种的多个 population 当多个物种）。不允许灭绝后再人为补种、加载存档重试或人工再次注入；跨地块转移不能算出生。若只过500日未过1000日，标明 `PARTIAL_500D`，不报 S 通过。

**S3 无人干预稳态**：在第五个进化事件和最后一次玩家操作两者中较晚的日期之后，才开始1000日无人干预窗口；期间不得追加改温湿/增减草/投放/强制进化/临时补充食物。检查每种最后200日的逐日数量、后100日与前100日均值比（推荐 0.75–1.35）、增长斜率、最低值、周期性震荡；植物资源不长期归零，捕食者不无限暴涨，也不将 K 作为刚性数量上限。若有正常的周期波动超出建议区间，可人工归类“存活但未证实稳态”，须证据与延长测试，不能放宽硬验收。

**S4 真正使用迁徙**：运行世界至少包含**7个连接的合法六边形地块**，至少3种可区分的温湿/地形资源生态条件，至少3种不同物种在≥2个地块有**已完成的迁出→迁入事件**，总成功迁徙事件≥20，并覆盖至少3对不同源/目标地块。迁入影响真实生态 K/竞争/捕食，至少一种迁入后能在新地块持续≥100日；迁出地、迁入地以及物种全局账必须一致。迁徙不能在测试中关闭而仍报综合 PASS。此处门槛用于证明机制确实被执行，并非鼓励制造毫无生态理由的迁徙。

**S5 完整性与可重复性**：每一次迁徙的源地减少量=目标地增加量（允许明确区分同日出生、死亡、正式进化与合并，跨地块汇总应对得上），不存在负种群、重复结算、凭空物质增加、非法高度跨越、违反目标容量与冷却、同日乒乓来回或幽灵复制。正式进化分化时母群与子群转移及付款成立。C/D捕食配额与旧群落没有回归性破坏。

**S6 多 seed**：冻结最终生产公式及测试政策后，用事先固定的 3 个 seed（240、241、242）对同一规则、地图、允许的玩家策略执行，不为每个 seed 偷偷改数值/手调时点。三个 seed 都满足 S1–S5 才称 **`S_PASS_3SEEDS`**；单个 seed 达成只记 `S_SINGLE_SEED`。同 seed 重跑至少1次，关键事件与汇总 hash 一致。时间不足时先拿1个 seed 完整运行，再多 seed，不得用不足样本宣称全局稳健。

**用户体验观察（不作硬性作弊目标）**：统计第一种至第五种正式进化的发生日期、模拟日对应现实分钟（仅以游戏真实倍速换算）、玩家操作次数和多地块观察成本，判断是否符合已有“4物种约15分钟”的体验目标；不要擅自加速生态或修改游戏时间比例来让五物种看上去更快。

## 五、具体研究、实验与修复准则

### A. 进化与动态 K

1. 从源码整理真实的每日计算顺序：环境恢复→摄食/竞争→捕食→能量与 K 估计→自然变异→繁殖/死亡→正式进化→迁徙（**此顺序只是待查假设，必须以实际代码为准**）。给出真实顺序及同日延迟影响。
2. 每种群、每地块逐日收集 `N, K_est, food_available, food_received, need, sat_ratio, births, starvation_deaths, predation_deaths, fitness, body, move, fertility, trophic, plantStock, plantRecovery, location`，另记目标种进化门槛、当前原地已存在目标的拒绝原因。字段若不可观测标 NA；允许加**只读 instrumentation**，不改变公式输出与 RNG 调用顺序。
3. 诊断彩鸡在+100到+500下降的根因：母群抢食？本地食物份额错误？K 以旧竞争者估算？母子分化付款后缺少长期支撑？收益不足但变异仍被采纳？优先用有/无母群、环境固定/脚本操作的配对试验来区分因果。
4. 对菇狸对照同一种子“继续玩家操作”与“正式进化后冻结玩家操作”：定位**首次可观测轨迹分歧**、当日实际操作、变化的食物供需、能量/捕食、死亡原因。不要只说“过度繁殖”。菇狸峰值1908不是天然错误；只有能量账、食物再生、系统性发散/失稳证据才支持调低增长。不能为了旧1000门槛硬删种群。
5. 候选数学机制必须能解释竞争者/捕食者/迁入改变后 K 如何更新；K 只是自适应估计，不能把 N 强钳制为 K。证明分母非零、N=0/极小种群、食物=0、多人竞争、初始高资源、极高捕食压力、突发迁入的处理；标清单位、非负、单调性、质量约束。优先复用原变量，避免调参维度膨胀。
6. 一次最多并行评估**3个公式/机制候选**、**2轮生产修改**。每次先离线小模型验证假说，再进入 Unity；候选必须在同一测试矩阵上比较，不能仅用“看起来好”选择。

### B. 迁移/合并/地块生态约束

1. 先单测：平地邻居；高度差1；高度差2阻止；目标过载；本地接近 K 被动迁出；目标环境更适宜主动迁出；相同物种已有群落的合并与基因交流；无合法邻居；种群 <10 禁迁；单次迁出 >100 封顶；多地块循环迁出冷却与阻止同日重复结算。**这些是设计约束起点，必须核对实际最新代码/冻结版本，发现冲突时记录而非擅改为新规则。**
2. 所有同日迁徙以**事件/账本**追踪：day, speciesId, lineageId, from, to, beforeN, emigrants, immigrants, afterN, reason, fitnessFrom, fitnessTo, KFrom, KTo, cooldown, rejectedReason。记录同日出生/死亡/正式进化应从守恒等式独立扣除，不能把重复计算当合法增长。
3. 迁徙发生后重新计算受影响地块生态竞争份额和动态 K（按真实结算次序避免重复收费），检查“目标满负荷→立刻迁回源地”的振荡与迁移死循环。若当前架构只有单地块驱动器，不得用模拟器外部瞬移脚本充当迁徙；先修正真实多地块运行与事件采集。
4. 海水同连片水域合并计算、异水域分化10%、陆海转换等，如与本轮所选物种路径无关仅做静态不破坏检查；若被选路径依赖这些行为必须给出真实跨生态位测试，且遵循原游戏规则。

### C. 从2种到5种的逐级场景

1. **E2**：在受控单地块/双地块中分别重复彩鸡和菇狸的正式进化；对比继续操作 vs 停止操作；要求正式进化后的母种/子种至少500日存活且没有明显长期崩塌。
2. **M2**：两种食草竞争+迁入迁出；观察资源份额重新分配、弱势补偿、K 变化与迁徙事件完整账本。
3. **P3**：双食草+捕食者+迁徙；要求不出现零成本捕食、假食物、不可逆全灭；已有 A–D 测试仍应可复现。
4. **E3→E4→E5**：先从现有生物网建立5个合法目标路径表（source→target、营养级、适温适湿、先决条件、阶段可能冲突），搭建 **至少7地块** 的世界。推荐 1 个核心生产区、2 个食草竞争区、2 个气候缓冲区、1 个捕食者区、1 个迁徙走廊；具体资源/温湿/高度以游戏实际地形与物种图为准，不能发明与图不符的最适值。
5. 允许玩家操作按**确定的可观察状态政策**作决策（例如资源下降触发既有合法恢复按钮），但输出完整脚本/政策与事件轨迹，禁止按未来 RNG/隐藏生态数值针对单个 seed 魔改。第五次成功正式进化后**必须停止所有操作**，从最后一次操作之后开始长期观测。
6. 当进化发生但第五种不能共存时，分别做：a) 固定生存段无后续操作；b) 去掉迁徙；c) 只保留资源压力；d) 只保留捕食；e) 冻结变异。上述均作为**诊断对照，不能替代真实综合验收**。标记首个崩溃链条及其干预前驱。
7. 最终输出地块×物种×日期热图或 CSV（不要求美术绘图）、食物/捕食网拓扑及迁徙图。明确每个物种真正在哪些地块长期存活。
